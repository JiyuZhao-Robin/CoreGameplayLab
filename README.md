# Helios Core Gameplay Lab

这是从主项目拆出的独立 Godot 单恒星系工业管理游戏核心版本。它保留完整玩法规则、内容数据、存档、离线模拟和纯控件操作界面，不依赖主项目中的图片、模型、Shader 或 UI Art Pack；核心完成后再进入正式美术制作。

当前 Save Schema 为 35，内容版本为 `1.29.0-single-system-core`。schema 24–35 采用显式逐版本迁移；旧全局库存迁入 `earth_orbit`，Location、物流、在途 Shipment、施工、生产线、舰船装配、研发和采掘点状态均保留。旧四巨构状态只进入历史归档，不会伪装成新终局进度；逐物品消费统计从 schema 35 开始累计。

## 设计文档

- [正式设计方向](docs/Design_Direction_zh_CN.md)：已确认的产品定位、工业深化目标、系统边界和下一阶段范围。
- [核心玩法实现审计](docs/Core_Gameplay_Implementation_Review_zh_CN.md)：当前实际实现、测试覆盖、缺口和扩展价值评审。

设计方向描述“接下来要成为怎样的游戏”，实现审计描述“当前实际上已经做到什么”。两者发生差异时，不应把目标方向误报为现有功能。

## 直接启动

1. 打开 Godot 项目管理器，点击“导入”。
2. 选择本仓库中的 `project.godot`，然后点击“导入并编辑”。
3. 按 **F6** 运行当前场景，或按 **F5** 运行项目。

也可以在仓库根目录运行：

```bash
godot --path .
```

## 当前玩法流程

1. 在左侧产品导航的 **星系地图** 上点击恒星系内的任意天体/区域。`UNKNOWN` 只显示地点存在；使用装有传感器或深度勘测系统的实体舰船，按 `DETECTED → SURVEYED → DEEP_SURVEYED` 获得逐层工业情报。
2. 在 **舰队** 将已经安装采矿激光的初始勘探船调入采矿舰队。
3. 在 **前线作业** 启动近地永久采集点，并使用顶部 **10×** 或 **50×** 加速。
4. 在 **工业与建设** 的“生产配方”工作区将混合粗矿分离成铁矿和铜矿，分别精炼成铁锭和铜锭；再用 **2 铁锭 + 1 铜锭** 组装结构框架。
5. 保留第一套结构框架，再准备 **4 铁锭 + 2 电子元件**，进入“设施建设”建造轨道铸造厂。再生金属只是可选回收物，不再是核心建筑的必需材料。
6. 初始工程制造中心可直接用铁锭和铜锭持续组装基础电子元件。建立研究中心后推进科研；在 **星港与舰队** 完成造船、改装、前列/中列/后列编队与补给，再进入远征。
7. 在地点 **物流** 页按货类配置通用货运、大宗拖船、质量投射器、低温运输舰或高速快运舰；专用舰运必须分配当前装配满足货舱、角色插件、推进插件和科技要求的真实舰船。
8. 在已勘测地点选择兼容的 Extraction Method，通过正常 Construction Project 建设永久采掘点；地点的真空、大气、辐照、辐射、建设难度、维护严重度与航线周期会共同改变生产、维护和物流选择。

核心规则现已覆盖：地点独立分级库存、受枢纽和航线吞吐约束的多跳物流、真实 Factory + Production Device + Production Method、满仓停机与自动恢复、维护/建设/研发/造船统一需求登记、当前经济诊断、生产依赖图、只读目标产能规划、最短瓶颈链、有限条件自动化、矿点潜力/品位/工艺链、工业等级与能源/冷却/结构约束、普通舰载插件的装配方案与整套 BOM 制造、特殊装备 UUID、真实造船与改装工期、由装配决定的后勤工业职责、八个技术能力域、多阶段研发项目、实验技术成熟度、技术外溢、真实原型与实地测试、工业体系改造、舰队生命周期和三线编队战斗。

经济闭环由内容校验器和自动化测试共同约束：所有战略消耗品必须有可重复来源；所有常规工业产物必须有后续用途或回收路径。结构框架、电子元件、普通舰载插件的整套装配、维修物资、反应堆部件和数据核心都具有确定性资源路径，战斗掉落只提供额外收益，不再承担主线唯一入口。

第二阶段已将设施扩建、电力/冷却/结构/仓储/物流容量和巨构纳入同一建设队列。项目按优先级分享有限建设能力，渐进消耗工业机床、重型结构段、精密执行器和电力总线组件；容量和工业等级只在项目完工后改变。

第三阶段建立的工坊、工厂、工业综合体和自动化工业区仍通过建设项目跃迁；钢铁与重型结构纵向链仍提供会真实改变投入、速度、能耗、冷却和废料的替代工艺。第七阶段已经废止手工生产百分比和地点职业加成：同一 Factory 的运行产线自动共享真实设备吞吐，产业分工只由资源、设备、能源、规模、精通、维护与物流自然形成。

第六阶段把关键科技改造成 3–5 个有意义阶段的研发项目。研究容量不可库存；Knowledge、材料/组件、基础设施和运行条件门槛会直接调用现有工业。推进试验必须制造实验件并执行真实试飞，聚变计划必须制造维护组件并运行真实能源阵列；SYSTEM 成果只解锁工业改造方案，采用时仍需资本品、建设能力、工期和停机。

第七阶段恢复了由真实 Storage Capacity 限制的四类星球库存。生产满仓会进入 `BLOCKED_OUTPUT`，有空间后自动恢复；O&M、建设、研发与造船都登记可追踪的 Demand Source。工业页的“经济诊断与规划”会显示库存、生产、消费、净变化、承诺需求、阻塞原因和最短瓶颈链，并提供与 Simulation 共用公式的只读吞吐规划器。第一版自动化只允许经授权的暂停/恢复、航线策略和项目优先级事务，不会自动扩建产业链。

第八阶段限定在唯一 `sol` 恒星系。每个 Location 使用统一环境模型；资源点没有常规枯竭，而由 Sustainable Extraction Potential 限制可长期支撑的工业规模。勘测任务真实占用舰船、装配能力、燃料、维护品和航行时间；永久 Site Development 复用普通建设、地点库存、能源、仓储与物流。Planner 会比较目标吞吐与当前已勘测潜力，并给出追加勘测、深度勘测或升级开采方式等只读解法。质量投射器等运输方式也读取相同地点环境条件。

核心终局只有 `stellar_energy`。它从研发与候选地点深度勘测开始，依次建设前进基地、锚定基础、主体框架、能源骨架、主功能系统、系统集成和最终调试；每阶段使用真实工地库存、预留、物流、建设能力、能源、散热和维护，最终展示材料、资本品、运输、工期、峰值建设/功率和主要供应地点统计。

左侧的“当前引导”会根据实时状态给出下一步。所有按钮都调用复制后的真实核心命令，不是伪流程。
