# 星球共享库存与道路工业

> 设计权威 · 2026-09-10。首批道路/共享库存功能已通过主 agent 的定向测试；这是分阶段重构，不表示完整工业重构或发布验收完成。

## 1. 唯一目标与范围

让玩家用工业力量“征服星海”。本地规划负责产能、用地、资源与供电；运输战略集中在星际航运，不引入本地铁路、长途卡车线路、分区库存或区间调拨。

本文件替代旧工厂文档中要求 CARGO/POWER 端口拖线、独立实体仓库库存的设计要求。舰船装配画布的独立 DSPONLINE 设计不受影响。

参考 [Anno Union：Pushing Carts](https://www.anno-union.com/devblog-pushing-carts/) 的道路取送货、仓库装卸和岛屿库存关系；不照搬其人口、市场或整个经济系统。

## 2. 已确定的玩法规则

### 星球库存

- 一颗星球共享一份经济库存。当前代码以 `world.location_id` 绑定的 `locations[location_id].inventory` 为唯一权威；同地点多个画布也共享它。
- 每种物品分别享有容量。铁矿满仓不能挤占铜矿、电子元件或其它物品。
- 仓库是共享库存的道路接入点与装卸设施，不保存另一份经济库存。两个不相连路网里的仓库仍访问同一份星球库存，不需要在仓库间建设铁路或运输线路。
- 机器输入、输出缓存和运输中货物是真实资产，但不属于可直接取用的仓库库存。总资产统计可相加，仓库可用量不能将它们混入。
- 断开道路不删除库存，不让物资凭空丢失。仓库拆除导致容量降低时保留已有超额库存，阻止继续入库，直至恢复容量或消耗库存。

### 道路、电力与自动运输

- 已建道路格通过上下左右相邻连通；建筑沿占地边缘接入。未建幽灵不参与任何连通计算。
- **不接道路就不接通电力。** 电源与用电建筑必须属于同一个道路连通分量。道路本身不需要电力，切断道路立即重新计算供电。
- 建筑不充当跨道路分量的桥接器。接触多个分量时采用确定性的单一接入分量。
- 机器自动从附近生产者取料；直接消费优先，剩余产品送到服务范围内、道路可达的仓库，进入星球库存。机器也可通过可达仓库领取星球库存。
- 每次搬运有真实在途货物与耗时，受服务范围、搬运能力和装卸能力限制，不瞬间改写所有机器库存。
- 仓库容量升级与装卸能力升级是不同效果；道路升级提高运输速度，而不是暗中扩容。
- 已取货后源缓存变空不影响交付。断路、目标失效或目标满仓使任务阻塞，货物仍属于在途任务，恢复后继续处理。
- 不再给玩家提供行星内的物资/电力端口连线、物资过滤线路、手动仓库导入导出。

### 星际物流

现有 `LogisticsEngine` 继续负责跨地点航线、船舶、运力、成本、在途货物、到货容量预留和重试。道路不是 `content.logistics_routes` 的成员；铺路不会修改星际 ETA、推进剂成本或船舶资格。

### 保留的建设方向

星球逻辑边界决定实际建设面积。当前 Earth 为 1024×640，月球/小行星带为 1536×960，外层大型世界最高 4096×2560 tiles（具体以 `world_profiles` 为准）。地形只为当前视口构建纹理区块，最多保留 96 个区块网格；缩远时提高采样步长，目标地形单元预算 8192。矿区是稀疏、不规则描述，不分配整颗星球的 Tile 数组。视口隐藏不停止工业模拟。

建设已经改为“制造成品建筑 → 库存 → 部署”。部署扣一件未预留建筑成品，缺货留下幽灵，到货后自动部署；没有现场建材拨款与施工时间条。机器配方配置复制保持可用。整片区域蓝图仍是独立待办，不把机器配置复制冒充区域复制。

### 玩家选址与开局包（覆盖旧散装仓库/太阳能开局）

矿区近景最多使用 128 个细节网格；缩到低于 1 px/tile、进入简略视图或超过细节预算后，使用真实物品图标。大星球总览不会把几百个矿区反复挤入小缓存、每帧重新构建矿石网格。

新游戏没有预放工业建筑。初始库存持有一件星球开发核心，工业画布首先只提供核心选址；玩家在合法地块部署后，核心成为共享仓储、道路运输接入点并提供 400 kW 电力，同时一次性发放 **2 矿机、2 锻炉、1 自动制造机**。不再携带初始太阳能；后续发电设施从机器制造。远端世界需要运输建筑成品与开发核心，不重复赠送地球开局包。

水体、山脉禁止放建筑和新道路，非法放置事务完全回滚。起始安全区保留可建设地形和铁/铜矿；更远处有实际不规则资源斑块。当前矿区仍使用持续开采速率，不声称已经实现有限矿量耗尽。

### DSPONLINE 工业内容与美术适配

`data/dsponline_industry.json` 保存 78 个源物品映射、39 栋建筑、80 条源配方和 42 项建设引用；另外生成 39 个可运输的建筑成品和制造配方、5 条矩阵科研选择变体。导入器记录源 SHA-256 与科技映射，六种同义材料保留当前 canonical ID。其它内容使用 `dsp_`/`grid_dsp_` 前缀。

- 普通冶炼、制造、炼油、化工、分馏、粒子对撞机使用同一配方/缓存/背压模拟。升级机器共享其基础机器的兼容配方。起步锻炉和自动制造机也能生产对应 DSP 基础材料及全部建筑成品。
- 燃料机按路网实际调度功率扣燃料，保留剩余 MJ；未装燃料不产生额定功率。蓄电器按实际多余电力充电，缺电时放电；能量交换器的充/放电配方必须结清一整件蓄电器的能量，半途不允许换方返还完整能量物品。
- 喷涂机满供电后，在同路网、服务范围内自动服务机器，增产剂通过正常道路货运进入缓存，先预留额外产物空间再消费喷剂。三档喷涂对应 1.3/1.7/2.5 倍机器电耗；充放电不允许增产电池。加速模式断开服务会丢弃尚未结算的本周期进度，避免免费保留未付喷剂的加速工作。矩阵科研消耗玩家选定的矩阵，并作为现有研究系统的工作积分；不另建平行科技树。
- 太阳帆/火箭消耗实体输入后增加戴森效果。帆基础寿命 1200 秒、88 kW/帆，结构 960 kW/点；接收站上限 6000 kW，光子产出必须分到真实恒星能。源完整球壳几何、帆吸收与恒星亮度研究并未照搬。
- 建筑制造中心提供成品建筑制造。银河出口的四种材料项目、明确确认后的黑洞销毁、空间站 16 项材料交付以 `world.dsp_effects` 记录；空间站按材料顺序交付，非原作四组并行施工。黑洞改为道路单物品配方，不恢复三个手动端口。
- 时间扭曲仅消费普通用电及蓄能之后的可再生剩余功率，按源阈值计算倍率；仅影响在线实时推进，不倍乘显式离线补算。不导入上游账号、联网活动或银河积分商城。
- 物流站/枢纽适配为本项目道路与共享库存的接入设施；保留现有星际航运，不引入第二套 DSP 端口/物流船模拟。
- 气态巨星生成氢、重氢和可燃冰气态资源区，轨道采集器能覆盖其兼容矿区并通过道路送仓；不是只导入一个无法使用的建筑条目。

真实生成资源：核心独立透明图、地形 4×2 图集、39 建筑 8×5 图集、78 物品显式切片图集。物品图片不是均匀网格，必须消费 `materials_atlas_regions.json`，不能按 10×8 猜位置。各目录 `PROMPT.md` 留有提示词和工具来源；palette、实体、幽灵、配方选择与库存/在途图标共同消费这些资源。

## 3. 冻结的模块契约

### 状态与只读快照

`Factory Workspace protocol v1` 采用新增字段扩展；不是 Location Operations 协议。

| 用途 | 字段与形状 |
| --- | --- |
| 世界持久化 | `logistics_mode = "PLANET_SHARED_ROADS"` |
| 世界道路 | `roads: Dictionary`，键 `"x,y"`，值 `{x:int, y:int, tier:1或2}` |
| 世界在途任务 | `road_shipments: Dictionary`，键为任务 ID |
| 任务资产归属 | `source_id`、`target_id`、`destination_kind:"WAREHOUSE"或"ENTITY"`、`cargo:Dictionary` |
| Factory 只读快照 | `roads:Array`，稳定排序；`road_logistics` 为诊断摘要 |
| 道路任务只读投影 | `road_shipments:Array`，与持久化 Dictionary 不同；按 ID 排序，提供收发端点、物品/数量、阶段、进度、路径位置和剩余时间下界 |
| 建筑投影 | `road_connected`、`road_component_id`、`power_factor` |
| 共享库存投影 | `shared_inventory`；仓库实体 `inventory` 为空，不重复持有共享库存 |

任务其余运行字段以 `FactoryRoadTransport` 实际实现为准，不建立第二套 UI 自有调度状态。

当前每个任务只调度一种物品。异常的多物资 manifest 会保留全部货物并标为 `BLOCKED_MANIFEST`，不会交付一种后清掉其余物资。机器换配方后的退料仍占用原机器的搬运者，直到返仓结束；不通过改换任务 owner 凭空生成空闲车辆。

### 命令

- `BUILD_ROAD {tiles:[{x,y},...], tier:1|2}`
- `REMOVE_ROAD {tiles:[{x,y},...]}`

通过 `Game.execute_factory_command` 的事务、命令 ID 幂等、拓扑版本校验执行。单笔最多 2048 格，App 对重复坐标去重；同等级已存在道路是幂等操作，不再次收费。非法等级、越界或新路覆盖建筑/施工占位导致整批拒绝，不留下半条路。

旧 CARGO/POWER 命令和仓库导入导出不允许绕过新模型。保留的历史兼容方法不代表玩家仍有旧物流玩法。

### 库存桥接与守恒

```text
Location 库存 / 机器输出
           ↓ 扣除原保管域
road_shipments[job_id].cargo
           ↓ 到达且目标有空间
机器输入 / Location 库存
```

`SimulationEngine.factory_inventory_context` 将当前地点库存、未预留可用量、扣除外部预留后的剩余容量传入 `FactoryGridSimulation.advance_world`。这是临时引用，绝不能保存到 world，也不能把共享库存复制进每个仓库。

`FactoryRoadTransport` 调度本地任务；`LogisticsEngine` 只负责跨地点运输和共享目标容量查询/预留，不再另起一套本地调度权威。`SpaceGameState.factory_world_item_ledger` 单独统计 RoadTransit，不将转移视为生产或消耗。

旧实体仓库中的存货一次性转入 Location，之后该实体库存清空。最低限度保证重复协调、事务复制、存档归一化不重复加货；不扩展为长期旧模型兼容工程。

## 4. 首批实现与后续工作

首批已实现且通过定向测试：

- 道路铺设、拆除、强化命令，边界和占地校验。
- 道路图供电、自动本地搬运、单一星球库存接入。
- 真实在途资产、断路阻塞、独立物品容量。
- 底部道路工具、道路贴图、仓库共享库存与接路状态；普通空白左键拖动画布保持可用。
- 关闭当前玩家路径的旧工厂端口连线和仓库手动导入导出。

明确后续项目，不能作为本批已实现项：

- 整片区域蓝图、批量旋转和完整复制粘贴（缺货幽灵已实现；当前机器配置复制不等于区域蓝图）。
- 有限矿量开采、地形改造；地形阻挡与不规则矿区生成已经接入。
- 仓库装卸升级的完整内容/界面、完整车辆美术及动作、服务范围可视化。
- 上述车辆美术指完整搬运车/无人机实体及动作；下方已接入的是实际在途货物图标，不冒充完成车辆美术。
- 全部旧端口内部兼容代码和旧测试的后续清理。

## 5. 临时平衡值与美术验收

初始库存没有铁锭，基础道路 Tier 1 暂时免费，避免“先有铁才能铺路、先铺路才能产铁”的死锁。Tier 2 新建/升级每格消耗 1 铁锭；已经强化的格不重复收费。默认速度 Tier 1 为 4 tiles/s、Tier 2 为 8 tiles/s。这些是首批临时平衡值，调整需由主 agent 统一同步代码、说明和测试。

本批道路资源为实际生成的 [road_surface_v1.png](../assets/ui/factory/roads/generated/road_surface_v1.png)，[生成说明](../assets/ui/factory/roads/generated/PROMPT.md)记录提示词与工具来源。正常近景应加载纹理；预览、选中提示及远景 LOD 可用几何表现。几何占位不能冒充已完成美术，也不宣称本批完成所有建筑和地形美术。

默认每栋生产建筑一名搬运者、每次一件货物，仓库同时两份装卸能力、每次装卸一秒；全画布最多 64 个活跃任务作为首批安全上限，派单游标轮换以避免固定 ID 饥饿。`road_logistics.capacity` 的单位是并发搬运者，不是固定件/秒。距离、道路等级、装卸等待都会改变实际吞吐。这些默认值仍需后续大工厂平衡与性能验证。

## 6. 功能验收

主 agent 在最终交付前记录实际运行结果；代理报告和静态检查不能代替验证。

- 无铁初始库存可铺设基础道路并启动生产。
- 命令失败原子、重复操作不重复扣费；道路严格受世界边界限制。
- 铺路立即供电、断路立即断电，幽灵不导电。
- 自动取料、生产、送仓有耗时且每件货物恰有一个保管域。
- 断路、满仓、事务归一化不丢失在途物资；跨地点库存不混用。
- 同星球仓库共享库存，各物品容量独立；UI 不重复计算。
- 道路工具发命令，不直接修改 Game.state；空白左键拖动、底部工具和固定比例布局无回归。
- 道路美术实际加载；视口裁剪和区块索引工作。
- 只运行本次功能及受影响的标准测试，不启动 J1–J10 全链路。

### 运输反馈补充（2026-09-10）

- 点仓库、矿机或生产机，检查器的“道路配送”显示与该建筑相关的真实收/发任务、物品贴图、数量、装货/运输/卸货进度，以及断路、目标满、目标失效等阻塞原因；任务完成就移除。列表限高内部滚动，不挤压固定页面布局。
- 剩余时间是当前运输与装卸工作的下界，不含尚未确定的排队延迟。阻塞任务显示暂无预计到达时间，不能继续虚假倒数。
- 道路货物图标沿权威快照路径移动；混合道路等级的位置按各段速度投影。只在前后两个已观测位置之间平滑，不越过最新模拟进度，也不循环播放虚构货流。断路停住，完成消失。
- 生产建筑仅在真实产出状态下对已有建筑贴图做运行明暗变化；缺电、缺料和输出满时停止。未追加伪车辆占位美术，复用现有 agent 生成的建筑/物资图集。
- 货物按路径区块筛选可见候选、最多绘制 64 个图标，并裁切至星球和视口；低于 0.75 px/tile 不画个体货物。overview、减少动态效果和超动画预算时保留快照状态，不开启连续动画重绘。
- 修正工业物资表仍按旧实体库存显示为 0 的问题：`stored` 来自唯一共享库存，`available` 只取未预留量，不再相加；生产暂停时已有库存行仍保留。
