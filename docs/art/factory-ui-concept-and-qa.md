# Industrial UI: concept and screenshot review

The user requested a complete screenshot review, analysis of released-game UI/art,
an approved-by-integrator foundational concept, and close implementation of it.

## Visual reference analysis

- Factorio's [production GUI](https://www.factorio.com/blog/post/fff-337) was
  inspected from the developer's published screenshot. Its strength is immediate
  production/consumption comparison, aligned quantities and repeatable item rows.
  Helios uses that information hierarchy with quieter color and larger type.
- [IXION's official images](https://www.kasedogames.com/ixion) were inspected for
  material language: layered industrial structures, warm process light inside a
  cool environment, and legible building silhouettes. Helios uses original art.
- Local `D:/Projects/DSPONLINE` provides practical port preflight, LOD, honest
  flow animation, producer tracing and BOM inspection references. No raster
  screenshots were found there. Its branding, fonts and image assets are not
  copied. See `third_party/dsponline/SOURCE_SCOPE.md` for source-use boundaries.

## Authoritative concept

`docs/art/concepts/factory_operations_overview_concept_v2.png` was generated using
built-in ImageGen and visually inspected by the integrator. It is the target for
the navy/slate surfaces, cyan selection, amber construction, panel hierarchy,
visible panoramic illustration, four KPI cards, four illustrated stage cards,
and 40/60 bottleneck/planner layout. Generated sample quantities and incidental
population/date text are illustrative, never implemented as fabricated metrics.
Existing shell controls and translated labels remain functional game controls.

The initial reference capture is `artifacts/ui/industry_before.png`. Reference
game screenshots stay in ignored `artifacts/ui/references/`.

## Required comparison captures

- Fresh-game overview and its deployment status (guidance remains in the task system).
- Established overview with real running machines and waiting construction.
- Entire build canvas, visible building artwork, connections and build dock.
- Selected machine / recipe / ports inspector.
- Production page with actual material rates and blockers.
- Construction page with funding, missing materials and work progress.
- Chinese and English; 1440x900 and 1366x768 physical windows; explicit 100% and
  125% UI scale with the same 1440x900 authored design coordinate system.

Every discrepancy found in a capture is either corrected and recaptured or
recorded as a remaining limitation. Passing headless tests does not replace this
visual check. Concept images are not production UI backgrounds.

## Review log

The first live capture was rejected: the overview's ScrollContainer child did
not expand horizontally, status codes leaked into Chinese, the initial camera
framed an almost empty world, and the footer still claimed to await a snapshot.
These are real rendered findings, not headless-test inferences. The subsequent
implementation adds explicit fill flags, localizes operational status, defers
camera framing until the canvas is visible, and reports live telemetry.

The production board now compares actual item output and consumption alongside
machine/recipe/route cards. Construction exposes staged/required/deficit rows;
automatic supply means ongoing same-world factory storage, while unreserved
location stock is staged once when the placement command is accepted.

The v2 concept changes only copy and preserves v1 composition. The user rejected
tourist/tutorial wording. Full edit prompt and provenance are in
`concepts/factory_operations_concept_v2_prompt.md`.

## Final rendered verification — 2026-09-10

Final images are real Godot renders generated by
`tests/factory_operations_capture.gd`, with no persistence and no direct grants
of test inventory. All four capture runs returned success:

| Evidence directory under `artifacts/ui/factory-overhaul/` | Locale | Explicit UI scale | Physical window | Rendered content |
| --- | --- | ---: | --- | --- |
| `zh-100-1440` | Chinese | 100% | 1440 × 900 | 1440 × 900 |
| `en-100-1440` | English | 100% | 1440 × 900 | 1440 × 900 |
| `zh-125-1440` | Chinese | 125% | 1440 × 900 | 1440 × 900 |
| `zh-100-1366` | Chinese | 100% | 1366 × 768 | 1228 × 768 |

The narrow-window texture excludes the Window's pillarbox pixels; its dimensions
are checked against the single uniform 1440 × 900 keep-aspect transform. It is
not a second responsive layout or a cropped logical page.

Each directory contains fresh-game overview, established overview, canvas,
production, construction, selected-machine and selected-construction images.
Overflowing boards also have `05-*-bottom.png` evidence. The integrator visually
inspected all four standard Chinese and narrow-window pages; a read-only UI
worker independently inspected all four English and Chinese 125% pages plus
selected inspectors and production bottoms. The integrator inspected the final
construction terminology correction across all four configurations.

Capture-driven corrections include horizontal overview fill, localized statuses,
live footer initialization, accurate exception counts, readable small-zoom
building silhouettes, reduced route-label collisions, actual recipe I/O instead
of buffer counts, and `Constraint` instead of a contradictory `Blocked` label on
waiting-material construction. All affected focused tests were rerun by the
integrator; no unintended panel overlap was found in reviewed captures.

Implementation differences from the illustrative concept are intentional: the
existing functional global controls remain, quantities are actual game state,
building silhouettes reuse the project's original atlas, and the panorama is a
separately generated original environment. Long dependencies, production lists
and accessibility-enlarged boards scroll inside their authored regions. This is
composition/material-language reproduction, not a pixel-identical flattened UI.
