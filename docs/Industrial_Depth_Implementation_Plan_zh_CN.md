# 《Helios / Space Idle》工业深化逻辑实施方案

> 状态：评审草案，尚未据此开始玩法代码改造  
> 日期：2026-08-26  
> 范围：只讨论逻辑、规则、数据、内容和验证；不讨论美术制作  
> 上位设计：[正式设计方向](./Design_Direction_zh_CN.md)  
> 当前基础：[核心玩法实现审计](./Core_Gameplay_Implementation_Review_zh_CN.md)

## 1. 实施结论

设计目标可以在现有项目上渐进实现，不需要推倒当前模拟、地点库存、物流、舰船和存档系统。

正确方法不是继续向 `content.json` 追加大量资源和配方，而是先完成五项底层改造：

1. 统一阻塞原因和全流程验证。
2. 资本品经济和统一建设队列。
3. 多生产线、生产方式和工业规模。
4. 货运属性、运输方式和实体物流服务。
5. 标准模块实体化、目标产率规划与政策自动化。

之后再扩展技术代际、勘测、区域身份和巨构竞争。

推荐依赖顺序：

```text
全流程验证与统一阻塞原因
        ↓
资本品 + 统一建设队列
        ↓
生产方式 + 工业规模 + 地点专精
        ↓
货运属性 + 运输方式
        ↓
标准模块实体化 + 后勤舰船
        ↓
目标产率规划 + 条件自动化
        ↓
技术代际、勘测和巨构深化
        ↓
第二恒星系（以后）
```

实施顺序不能反过来。否则新增加的资本品、生产方式和货运类型会迅速增加阻塞组合，而玩家和自动化系统仍然无法解释为什么停工。

下一次实际编码应从一个范围受控的“钢铁—资本品纵向切片”开始，而不是同时改造全部 60 种资源和 91 项活动。

## 2. 现有系统如何演进

| 现有基础 | 可以直接复用 | 必须演进的部分 |
| --- | --- | --- |
| 地点权威库存 | 继续作为资源和资产所有权根节点 | 加入资本品、标准模块库存和货运属性 |
| 实体在途运输 | 保留真实扣货、在途、到达和多跳路径 | 按货运体积占用容量，支持不同运输方式 |
| 100 段建设项目 | 保留渐进消耗和持续建造 | 泛化为设施升级、容量升级、物流和巨构共用项目 |
| 设施等级 | 保留等级、扩建成本和规模效应 | 增加规模阶段、建设时间和资本品需求 |
| 电力、冷却、结构、仓储 | 保留地点限制 | 增加转运吞吐、特殊防护和升级项目 |
| 生产活动 | 保留配方、设施、科技和周期 | 分离产品族与生产方式，允许多条生产线共享产能 |
| 工业模块和插件 | 保留能力门槛与取舍 | 统一纳入生产方式、规模阶段和改造工程 |
| 舰船实体和槽位 | 保留舰船身份、装配、改装和生命周期 | 标准模块从 BOM 定义升级为实际库存资产 |
| 特殊装备实体 | 保留唯一身份和占用关系 | 与标准模块共用安装、拆卸和项目暂存规则 |
| 科研材料消耗 | 保留逐步消耗与阻塞 | 增加研究耗材、原型和实地测试阶段 |
| 工业模板、后台经济 | 保留地点模板和自动扩建基础 | 扩展为目标产率和有限条件自动化 |
| 巨构阶段 | 保留七阶段、材料流和完成效果 | 复用统一建设系统并增加中途规则效果 |
| 确定性模拟和离线推进 | 继续作为所有长期活动的运行框架 | 增加新资产与项目的确定性边界和守恒测试 |

主要代码演进位置：

- [`data/content.json`](../data/content.json)：新增资本品、生产方式、货运类型、运输方式、设施阶段和科技内容。
- [`src/core/game_state.gd`](../src/core/game_state.gd)：新增建设项目、生产线、物流服务和标准模块资产状态。
- [`src/core/simulation_engine.gd`](../src/core/simulation_engine.gd)：统一项目推进、工业产能分配、生产方式和资产转移。
- [`src/core/logistics_engine.gd`](../src/core/logistics_engine.gd)：按货运体积调度，支持运输方式和服务容量。
- [`src/application/game.gd`](../src/application/game.gd)：提供所有玩家与自动化共用的事务命令。
- [`src/core/content_database.gd`](../src/core/content_database.gd)：校验经济闭环、所有权、解锁、运输兼容和循环依赖。
- [`tests/headless_test.gd`](../tests/headless_test.gd)：加入各阶段规则、守恒和黄金路径测试。

## 3. 第一阶段：全流程验证与统一阻塞原因

### 3.1 为什么必须最先完成

增加资本品和生产方式后，一项工程可能同时受到以下条件影响：

- 前置科技。
- 设施和设施规模阶段。
- 资本品。
- 本地原料。
- 其他地点库存。
- 来源保留量。
- 在途货物。
- 路线和运输方式。
- 枢纽装卸能力。
- 电力与散热。
- 仓储。
- 建设能力。
- 维护材料。

如果这些系统继续分别返回自然语言错误，玩家、引导、规划器和自动化都会重复实现阻塞判断，并产生互相矛盾的结论。

### 3.2 统一阻塞代码

首批阻塞代码：

```text
MISSING_TECH
MISSING_FACILITY
MISSING_SCALE_STAGE
MISSING_CAPITAL_GOOD
INPUT_SHORTAGE
INPUT_IN_TRANSIT
ROUTE_UNAVAILABLE
TRANSPORT_MODE_UNAVAILABLE
ROUTE_CONGESTED
HANDLING_CONGESTED
POWER_SHORTAGE
COOLING_SHORTAGE
STORAGE_FULL
MAINTENANCE_SHORTAGE
CONSTRUCTION_CAPACITY_FULL
PROJECT_SLOT_FULL
MANUALLY_PAUSED
```

所有系统返回统一结构：

```json
{
  "status": "BLOCKED",
  "primary_reason": "INPUT_SHORTAGE",
  "location_id": "earth_orbit",
  "item_id": "industrial_machine_tools",
  "required": 8,
  "available": 2,
  "upstream": {
    "reason": "ROUTE_CONGESTED",
    "route_id": "belt_to_lunar"
  }
}
```

统一诊断应由核心层生成，界面只负责翻译和展示。

### 3.3 无作弊黄金路径

建立一个从默认新存档出发的完整自动流程：

- 不直接注入高级资源。
- 不跳过科技。
- 不手工修改区域解锁。
- 不绕过舰船建造和远征。
- 不跳过巨构材料与阶段。
- 最终完成第一次星际远征。

流程记录：

- 每个主目标的完成时间。
- 主要物品收入、支出和峰值库存。
- 生产、物流、研究、建造和远征等待时间。
- 各阶段首要阻塞原因。
- 路线和枢纽最高利用率。
- 舰队损失和维修时间。
- 是否出现不可重复资源依赖。

每个主要阶段保存一份开发场景快照，但黄金路径本身不能使用快照跳关。

### 3.4 正式节奏与测试倍率

把速度倍率集中到模拟配置：

```text
TEST_PROFILE
├─ mining ×10
├─ manufacturing ×10
└─ 其他可按测试需要独立配置

NORMAL_PROFILE
└─ 使用正式平衡参数
```

两种配置使用同一套公式、事务和内容引用，不能在测试模式绕过材料或规则。

### 3.5 完成条件

- 所有持续系统使用统一阻塞结构。
- 新存档能自动走到当前终局。
- 任意失败都能定位到具体命令和阻塞原因。
- 测试与正式速度配置分离。

## 4. 第二阶段：资本品与统一建设队列

### 4.1 泛化建设项目

当前建设项目演进为通用 `ConstructionProject`：

```text
ConstructionProject
├─ FACILITY_BUILD
├─ FACILITY_EXPANSION
├─ SCALE_STAGE_UPGRADE
├─ POWER_UPGRADE
├─ COOLING_UPGRADE
├─ STRUCTURE_UPGRADE
├─ STORAGE_UPGRADE
├─ LOGISTICS_HUB_UPGRADE
├─ TRANSPORT_INFRASTRUCTURE
├─ EXTRACTION_NETWORK
└─ MEGASTRUCTURE
```

每个项目至少保存：

```text
项目 ID
类型
所属地点
目标设施或基础设施
开始等级和目标等级
优先级
项目槽位
总工程量
已完成工程量
材料计划
已交付材料
在途材料
已消耗材料
当前状态
首要阻塞原因
```

### 4.2 地点建设能力

建设能力以地点为主，不是完全共享的全局进度条。

文明级工程协调能力可以提供：

- 跨地点建设上限。
- 工程调度加成。
- 远程施工效率。
- 可同时管理的项目数。

具体项目仍需要目标地点的：

- 本地工程设施。
- 建设能力。
- 资本品。
- 结构、电力和物流条件。

### 4.3 首批资本品

| 资本品 | 主要投入方向 | 主要消耗端 |
| --- | --- | --- |
| 工业机床 | 钢、电子、精密材料 | 冶炼厂、加工厂、装配厂扩建 |
| 自动化核心 | 电子、数据核心、量子组件 | 后台工业、无人采掘、条件自动化 |
| 热交换组件 | 铜、钛、陶瓷或超导材料 | 高能工业、聚变设施、外太阳系基地 |
| 电力总线组件 | 铜、电子、超导材料 | 电厂、船坞和高能工业 |
| 重型结构段 | 钢、钛合金、结构框架 | 大型设施、星港、巨构、大型船体 |
| 精密执行器 | 钢、钴、电子元件 | 采矿设备、模块、装卸和自动装配 |
| 船坞机械 | 机床、重型结构、执行器 | 船厂升级和大型船体生产线 |
| 物流装卸设备 | 机床、执行器、电子元件 | 物流枢纽、货运站、质量投射器 |

最终首轮规模可以扩展到 8–12 种，但每种资本品必须被至少两个持续系统消费。

### 4.4 避免资本品循环软锁

采用分层启动：

- 一级设施继续使用现有建筑框架和设施组件。
- 2–4 级扩建消耗基础机床、结构件和普通材料。
- 5 级规模跃迁开始消耗专用资本品。
- 10 级以后使用高级资本品。
- 永久保留低效、低技术的基础机床恢复配方。
- 资本品生产设施不能把自身唯一恢复配方锁在自身升级之后。

旧存档已有设施等级视为已经完成建设，不追溯扣除新资本品。

### 4.5 事务变化

原有即时操作：

```text
expand_location_industry(location, facility, +5)
```

改为：

```text
queue_facility_expansion(
  location_id,
  facility_id,
  target_level,
  priority
)
```

完成项目后才修改设施等级。取消项目必须明确处理未消耗、已交付和在途物资。

### 4.6 完成条件

- 所有设施和容量升级进入建设队列。
- 多个工程真实竞争有限建设能力。
- 工程按进度消耗材料。
- 资本品形成可重复、无循环软锁的生产链。
- 巨构与普通扩建争夺同一类核心建设资源。

## 5. 第三阶段：多生产线、生产方式和工业规模

### 5.1 当前结构需要解决的问题

当前模式更接近“一个设施运行一个活动”。这不足以支持：

- 同一大型工业综合体同时生产多个产品。
- 目标产率分配。
- 产品优先级。
- 多生产方式比较。
- 设施规模阶段。
- 自动化重新分配产能。

### 5.2 目标产业状态

每个地点设施拥有总产能，多条生产线共享：

```text
轨道铸造厂
├─ 等级：12
├─ 规模阶段：工业综合体
├─ 总产能：120
├─ 钢铁：50% 产能
├─ 钛合金：30% 产能
└─ 重型结构段：20% 产能
```

生产线状态：

```text
line_id
product_family_id
method_id
capacity_allocation
priority
cycle_progress
input_commitments
fractional_materials
theoretical_rate
actual_rate
status
blocked_reason
```

### 5.3 生产方式定义

生产方式与产品族分离：

```text
产品族：钢铁
├─ 常规炉法
├─ 电弧冶炼
└─ 真空高纯冶炼
```

每种方式定义：

- 输入和产出。
- 副产物和废料。
- 工程量或周期时间。
- 材料利用率。
- 能源需求。
- 散热需求。
- 维护需求。
- 货运体积变化。
- 设施和规模阶段要求。
- 科技与模块要求。
- 环境适用性。

### 5.4 统一产率公式

```text
有效产能
= 设施基础能力
× 分配等级
× 规模效应
× 供电覆盖
× 散热覆盖
× 维护覆盖
× 熟练度与专业度
× 生产方式修正
× 地点专精修正
```

最终实际产率继续受到以下硬限制：

- 本地输入库存。
- 本地内部转运吞吐。
- 输出仓储空间。
- 特殊防护和环境要求。

### 5.5 工业规模阶段

| 等级 | 阶段 | 规则变化 |
| --- | --- | --- |
| 1–4 | 工坊 | 单一基础生产方式、人工操作为主 |
| 5–9 | 工厂 | 开放替代工艺和初级模板 |
| 10–19 | 工业综合体 | 多产线、更多模块、地点专精和规模效应 |
| 20+ | 自动化工业区 | 后台生产、高级方法和政策自动化 |

跨阶段必须通过建设项目完成，不能达到等级后自动瞬时变化。

### 5.6 地点专精

首轮四类：

1. 大宗冶炼中心。
2. 精密制造中心。
3. 燃料与低温工业中心。
4. 舰船制造中心。

后续再增加物流转运和科研特殊材料专精。

专精切换需要：

- 建设时间。
- 改造工程。
- 资本品。
- 生产停机或效率损失。

### 5.7 内容落地顺序

不一次重写全部活动，依次完成四条纵向链：

1. 钢铁与大型结构。
2. 电子与自动化。
3. 能源与散热。
4. 舰船、维修与物流设备。

### 5.8 完成条件

- 一个设施能够合理分配多条生产线。
- 每条重点产业链至少存在两种有意义的方法。
- 方法至少改变三类实际约束。
- 地点专精影响合理布局，而不只是提供通用加成。
- 工业规模阶段带来能力质变。

## 6. 第四阶段：货运属性、运输方式和物流服务

### 6.1 物品货运属性

每种可运输物品增加：

```json
{
  "freight_class": "BULK",
  "freight_units": 4.0
}
```

首批货运类型：

```text
BULK
STANDARD
PRECISION
CRYOGENIC
HAZARDOUS
OVERSIZED
```

运输容量占用：

```text
货运容量占用
= 物品数量
× 单位货运体积
× 运输方式适配修正
```

### 6.2 生产改变货运体积

示例关系：

```text
100 单位混合原矿 → 400 货运体积
40 单位精矿      → 较低货运体积
20 单位合金      → 更低货运体积
4 单位精密组件   → 少量高价值货运体积
```

具体数值在平衡阶段调整，但必须保留“初加工减少大宗运输压力”的关系。

### 6.3 运输方式定义

每种运输方式定义：

- 支持货运类型。
- 基础容量。
- 航行速度。
- 装卸速度。
- 推进剂消耗。
- 能源消耗。
- 维护消耗。
- 所需设施和科技。
- 可用路线和方向。

首批建议先做：

1. 通用货运舰。
2. 大宗拖船。
3. 质量投射器。

第二轮加入：

4. 低温运输舰。
5. 高速快运舰。

### 6.4 物流服务

玩家不逐艘运输货物，而是把运输资产配置给路线服务：

```text
地球—月球通用物流服务
├─ 运输方式：通用货运
├─ 分配舰船：3
├─ 每分钟容量：120
├─ 支持货类：STANDARD / PRECISION
├─ 当前利用率：87%
└─ 优先级策略：科研组件 > 维修补给 > 普通材料
```

运输调度器继续自动生成实际批次。舰船分配只改变可用容量、成本和适用货类。

质量投射器等基础设施也提供物流服务，但不占用舰船。

### 6.5 路径选择

运输路径不能只比较时间，应在满足货类要求后比较综合成本：

```text
运输时间
+ 容量拥堵
+ 装卸时间
+ 推进剂
+ 能源
+ 维护
+ 转运次数
+ 特殊货物风险
```

玩家仍可锁定来源和路线，自动选择只负责默认调度。

### 6.6 完成条件

- 大宗原矿与精密组件占用不同运力。
- 至少三种运输方式有不同适用场景。
- 运输舰是实际分配的舰船资产。
- 远端粗加工可以显著缓解路线拥堵。
- 物流守恒仍覆盖来源、在途、项目和目标库存。

## 7. 第五阶段：标准模块实体化与舰船工业

### 7.1 标准模块的推荐表示

标准模块是实际资产，但同型号、同状态的未安装模块以库存数量表示，不为每个副本生成独立 UUID：

```text
地球轨道模块库存
├─ 采矿激光 ×8
├─ 民用反应堆 ×3
└─ 低温货舱 ×5
```

安装后，数量从地点库存转移到具体舰船槽位。拆下后返回对应地点库存。

特殊装备继续保持独立 ID、来源、状态和唯一占用关系。

### 7.2 模块所有权状态

标准模块只允许处于一个位置：

```text
LOCATION_STOCK
IN_TRANSIT
PROJECT_ESCROW
INSTALLED_ON_SHIP
LOST
```

特殊模块采用同样状态，但额外保存实体 ID 和历史。

### 7.3 造船资产流

```text
地点库存
→ 造船项目暂存区
→ 船体总装
→ 舰船槽位
```

船体总装需要：

- 重型结构段。
- 实际推进器。
- 实际反应堆。
- 实际散热和传感模块。
- 武器及辅助模块。
- 船坞生产线。
- 建造和试航时间。

模块进入项目暂存区后，不能再被其他舰船或项目使用。

### 7.4 改装资产流

```text
新模块：地点库存 → 改装项目 → 舰船
旧模块：舰船 → 改装项目 → 地点库存
```

项目取消时应恢复尚未安装的新模块和已经拆下的旧模块，不能丢失或复制。

### 7.5 旧存档迁移

当前舰船已经安装的普通 BOM 模块在迁移时直接转为舰上占用资产，不从地点库存额外扣除。

迁移必须保证：

- 当前装配不变化。
- 不凭空生成未安装库存。
- 特殊装备 ID 保持不变。
- 进行中的造船和改装项目重新建立暂存区所有权。
- 存档校验能够发现重复占用。

### 7.6 首批后勤与工业舰船

1. 大宗货运舰。
2. 低温运输舰。
3. 维修支援舰。
4. 移动建设舰。
5. 深空勘测舰。

货运舰提供共享路线或舰队容量，不引入逐舰拖放货物。

### 7.7 完成条件

- 标准模块可以批量生产和运输。
- 模块安装、拆卸、造船、改装和损失符合所有权守恒。
- 船厂不会根据装配 BOM 凭空生成普通模块。
- 后勤舰船实际改变物流、维修、建设或勘测能力。

## 8. 第六阶段：技术代际和研究项目

### 8.1 三类科技

```text
UNLOCK：开放新设施、模块、船体、地点和运输方式
METHOD：开放新生产方式
SYSTEM：改变工业组织体系
```

体系技术候选：

- 中心化工业。
- 分布式工业。
- 大规模吞吐。
- 精密制造。
- 舰队工业化。

体系可以改换，但必须通过工业改造项目消耗资本品、建设能力和停机时间。

### 8.2 研究耗材

首批研究耗材：

- 材料实验组件。
- 推进测试组件。
- 自动化数据核心。
- 舰船原型组件。
- 异常物质样本。

耗材必须由主工业链生产，不能成为孤立科研货币。

### 8.3 关键技术阶段

只有重要技术使用完整阶段：

```text
理论研究
→ 制造原型
→ 实地测试
→ 开放量产
```

优先用于：

- 新型采矿舰。
- 聚变反应堆。
- 质量投射器。
- 自动采掘网络。
- 星际引擎。

### 8.4 完成条件

- 新科技能改变已有产业和物流，而不只是解除配方锁。
- 原型是真实工业产物。
- 实地测试调用实际舰船、设施或物流任务。
- 体系切换有成本但不会造成永久选错。

---

## 9. 第七阶段：目标产率规划与条件自动化

### 9.1 先建立生产依赖图

内容数据库根据物品、产品族、生产方式和设施生成依赖图：

```text
目标产品
→ 选定生产方式
→ 中间材料
→ 原始资源
→ 设施产能
→ 能源、散热、物流和建设需求
```

第一版规划器要求每个产品族选择一种主要生产方式，再按图向上展开。

废料回收等循环活动先作为副产物抵扣，不进入主需求递归。后续确有必要时，再按强连通分量或线性求解处理循环。

### 9.2 只读目标产率规划器

输入示例：

```text
钢：40/分钟
电子元件：30/分钟
维修补给：10/分钟
舰船弹药：20/分钟
```

输出：

- 每种中间材料的理论需求。
- 各设施所需等级和规模阶段。
- 推荐生产方式。
- 电力、散热、仓储和维护需求。
- 资本品与建设需求。
- 各路线所需货运容量。
- 预计拥堵位置。
- 当前实际可达到的产率。
- 最短瓶颈链。

### 9.3 从建议到执行

按以下顺序开放能力：

```text
只读分析
→ 玩家确认生产计划
→ 玩家确认物流政策
→ 玩家确认建设项目
→ 授权自动维持目标
```

第一版不能让规划器直接改动整个经济。

### 9.4 条件自动化

自动化使用有限条件和动作：

```text
条件：库存、净产率、路线利用率、电网备用、项目状态
动作：调整优先级、暂停/恢复、修改物流目标、创建已授权扩建
```

所有动作必须：

- 调用正常游戏事务。
- 遵循材料、能源、物流和建设规则。
- 保存执行原因和前后值。
- 有冷却时间。
- 尊重手工锁定。
- 能被玩家暂停和撤销授权。

### 9.5 完成条件

- 规划器预测与实际稳定产率处于允许误差内。
- 玩家能看到目标产率为何无法达到。
- 后期无需逐条启动大量生产。
- 自动化不能复制资源或绕过限制。

## 10. 第八阶段：勘测、区域身份和巨构深化

### 10.1 勘测状态

```text
UNKNOWN
→ DETECTED
→ SURVEYED
→ DEEP_SURVEYED
```

逐步公开：

- 资源类型。
- 品位范围。
- 开采潜力。
- 环境危险。
- 特殊副产物。
- 固定采掘网络和特殊方法。

勘测必须实际改变部署、建设、物流或生产方式选择。

### 10.2 区域逻辑身份

| 区域 | 逻辑身份 |
| --- | --- |
| 地球轨道 | 建设、精密工业、总装和物流；结构容量昂贵 |
| 月球空间 | 真空冶炼、低重力制造、早期固定采掘 |
| 小行星带 | 大宗采矿、粗加工、质量投射和高维护 |
| 木星系统 | 气体、推进剂、聚变燃料、辐射和重力约束 |
| 外太阳系 | 低温工业、长周期运输和自治设施 |
| 深空 | 特殊物质、高风险、高维护和远端自治 |

这些区别通过资源、允许方法、容量、运输和维护实现，不依赖纯粹的地点产量加成。

### 10.3 资源枯竭顺序

工业深化版本只做勘测和永久基础点。

以后可以增加高品位有限矿区，但前置条件是：

- 自动勘测。
- 枯竭警报。
- 舰队重新部署。
- 物流重新规划。
- 固定设施迁移或改造。

### 10.4 巨构统一

巨构使用通用建设项目，按阶段定义：

```text
材料
资本品
建设能力
能源
物流要求
阶段效果
```

中间阶段立即产生实际效果。多个巨构和普通工业扩建竞争同一批资源与建设能力。

### 10.5 完成条件

- 每个区域带来新的工业问题，而不只是更高数值。
- 勘测信息能改变实际选择。
- 巨构中间阶段能改变能源、勘测、物流或自动化规则。
- 玩家需要决定巨构与普通扩张的优先级。

## 11. 首个实际编码纵向切片

第一批只完成“钢铁—资本品—建设—大宗物流”闭环。

### 11.1 内容范围

新增或改造：

- 工业机床。
- 重型结构段。
- 精密执行器。
- 物流装卸设备。
- 铁/铜初级处理方法。
- 钢铁生产方式。
- 通用货运。
- 大宗拖运。
- 小行星带远端粗加工。
- 轨道铸造厂升级项目。
- 物流枢纽升级项目。

### 11.2 玩家闭环

```text
小行星带采矿
→ 选择运回原矿或远端粗分选
→ 冶炼铁、钴和陶瓷
→ 制造钢
→ 制造工业机床与重型结构段
→ 在轨道铸造厂和物流枢纽之间分配建设能力
→ 获得更高产能或更高运输能力
→ 新产能再次扩大资本品供应
```

### 11.3 这一切片必须证明

- 加工地点改变货运压力。
- 生产方式影响材料、能源和散热。
- 资本品成为扩建的持续需求端。
- 扩建真实占用时间和建设能力。
- 铸造厂与物流枢纽升级存在优先级选择。
- 物流拥堵能被统一诊断。
- 没有循环依赖或经济软锁。

### 11.4 明确不包含

- 不同时重做全部产业链。
- 不做第二恒星系。
- 不做动态矿区枯竭。
- 不做完整条件自动化。
- 不做全部标准模块实体化。
- 不增加大量新战舰。

## 12. 存档和迁移策略

每个能够独立合并的状态改造都必须有明确存档迁移，不能等所有系统完成后一次迁移。

推荐顺序：

1. 增加通用建设项目并迁移当前建设队列。
2. 增加多生产线并迁移现有工业操作。
3. 增加货运属性，不改变旧货物数量。
4. 增加物流服务并迁移当前路线基础容量。
5. 增加标准模块库存并迁移舰上现有装配。
6. 增加规划器和自动化授权状态。

迁移原则：

- 现有资源数量不凭空减少。
- 已有设施等级不被回退。
- 已安装模块不需要玩家重新制造。
- 在途货物保持来源和目标。
- 正在进行的研究、建设、造船、改装和远征尽量保持进度。
- 无法无损迁移时必须明确版本策略，不能静默丢弃状态。

## 13. 必须持续验证的逻辑不变量

### 13.1 资产所有权

任意资源或资产只能处于一个位置：

```text
地点库存
运输中
项目暂存
舰船安装
已消耗或损失
```

### 13.2 数量守恒

- 运输前后总量守恒。
- 项目取消不会复制材料。
- 模块拆装不会复制模块。
- 报废回收只产生规则允许的回收量。
- 战斗损失明确记录为损失或残骸。

### 13.3 模拟一致性

- 一次离线推进一小时与分段推进一小时结果在允许误差内一致。
- 速度倍率不改变配方比例和资产守恒。
- 自动化和手工操作使用相同事务。

### 13.4 经济闭环

- 每个战略消耗品有确定性来源。
- 每个资本品至少有两个持续消耗端。
- 每个新中间物至少创造一种实际决策。
- 开局和迁移存档保留低效恢复路线。

### 13.5 可解释性

- 每个阻塞项目都有结构化首要原因。
- 根因可以追溯到上游资源、设施、能源或物流。
- 规划器和模拟器使用同一套生产与需求公式。

---

## 14. 不采用的实现方式

- 不先往内容配置中批量添加几十种资源，再补规则。
- 不为标准量产模块全部生成独立 UUID；只有特殊模块保留独立身份。
- 不用抽象市场准入率替代真实物流。
- 不让自动化直接修改状态或免费创建项目。
- 不让地点专精退化为无条件的通用产量加成。
- 不把设施 1–30 级做成同一个百分比连续增长。
- 不把关键生产方式做成无代价的高级版本。
- 不在诊断、警报和重规划完成前加入全面资源枯竭。
- 不在太阳系工业深化完成前开发第二恒星系。
- 不引入人口、市场、政治、逐机器布局或即时战术微操。

## 15. 推荐交付批次

### 批次 A：闭环基础

- 无作弊黄金路径。
- 统一阻塞结构。
- 测试/正式速度配置。
- 关键阶段开发快照。

### 批次 B：钢铁—资本品纵向切片

- 通用建设项目。
- 设施升级排队。
- 四种首批资本品。
- 钢铁生产方式。
- 货运体积。
- 通用货运和大宗拖运。

### 批次 C：完整工业资本

- 8–12 种资本品。
- 四条重点产业链。
- 工业规模阶段。
- 四种地点专精。
- 3–5 种运输方式。

### 批次 D：舰船工业

- 标准模块库存资产。
- 造船和改装暂存区。
- 五类后勤/工业舰船。
- 模块与舰船存档迁移。

### 批次 E：规划与自动化

- 生产依赖图。
- 只读目标产率规划器。
- 生产与建设建议。
- 有限条件自动化。

### 批次 F：技术、勘测与巨构

- 三类科技。
- 原型和实地测试。
- 分阶段勘测。
- 区域工业身份。
- 巨构中间规则效果。

第二恒星系不属于上述批次。

## 16. 工业深化逻辑完成标准

只有同时满足下列条件，才可以开始第二恒星系：

1. 新存档能够无作弊完成第一次星际远征。
2. 任意核心停工状态可以追溯到具体根因。
3. 所有设施升级都进入统一建设队列。
4. 资本品持续限制工业扩张，而不造成循环软锁。
5. 四条重点产业链都存在有意义的生产方式选择。
6. 地点容量和专精能改变合理工业布局。
7. 至少三种运输方式拥有不同适用场景。
8. 远端粗加工与中心精炼在不同条件下都可能合理。
9. 标准模块遵守生产、运输、安装和拆卸的资产守恒。
10. 五类工业/后勤舰船能够连接物流、建设、维修和勘测。
11. 目标产率规划器能解释设施、原料、能源和物流缺口。
12. 后期操作能够从逐条启动生产转向目标、警报和例外管理。
13. 科技能改变工业组织方式，而不只是解锁更高材料。
14. 巨构工程和普通工业扩张真实争夺建设能力。
15. 存档迁移、离线推进和自动化不破坏资产守恒。

## 17. 最终结论

从逻辑和核心内容出发，实现目标的关键不是增加更多系统，而是让现有系统形成更强的约束关系：

> **地点决定能够建设什么；  
> 生产方式决定如何使用资源；  
> 货运成本决定在哪里加工；  
> 资本品和建设能力决定扩张速度；  
> 技术代际决定工业如何重新组织；  
> 实体舰船把工业能力转化为前沿行动；  
> 自动化把不断扩大的网络提升到文明管理尺度。**

首个实际实现目标应是钢铁—资本品纵向切片。完成后，玩家会第一次真实面对：

> 应该在小行星带粗加工以节省运力，还是把原矿送回高效中心；应该先扩建铸造厂提高资本品产能，还是先扩建物流枢纽解决拥堵。

当这个选择能够由真实库存、产能、能源、建设和运输共同得出，并被测试完整验证时，项目就迈入了正式的工业深化阶段。
