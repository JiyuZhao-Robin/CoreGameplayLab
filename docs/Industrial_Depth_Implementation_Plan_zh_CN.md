# 《Helios / Space Idle》工业深化逻辑实施方案

> 状态：实施中；第一至五阶段核心规则已落地，第三阶段其余纵向产业链仍按 5.7 扩展
> 日期：2026-08-27
> 范围：只讨论逻辑、规则、数据、内容和验证；不讨论美术制作  
> 上位设计：[正式设计方向](./Design_Direction_zh_CN.md)  
> 当前基础：[核心玩法实现审计](./Core_Gameplay_Implementation_Review_zh_CN.md)

## 1. 实施结论

设计目标可以在现有项目上渐进实现，不需要推倒当前模拟、地点库存、物流、舰船和存档系统。

正确方法不是继续向 `content.json` 追加大量资源和配方，而是先完成五项底层改造：

1. 统一阻塞原因和全流程验证。
2. 资本品经济和统一建设队列。
3. 多生产线、生产方式和工业规模。
4. 货运属性、运输方式和实体物流服务。
5. 装配方案工业化、目标产率规划与政策自动化。

之后再扩展技术代际、勘测、区域身份和巨构竞争。

推荐依赖顺序：

```text
全流程验证与统一阻塞原因
        ↓
资本品 + 统一建设队列
        ↓
生产方式 + 工业规模 + 地点专精
        ↓
货运属性 + 运输方式
        ↓
装配方案制造 + 装配驱动的后勤职责
        ↓
目标产率规划 + 条件自动化
        ↓
技术代际、勘测和巨构深化
        ↓
第二恒星系（以后）
```

实施顺序不能反过来。否则新增加的资本品、生产方式和货运类型会迅速增加阻塞组合，而玩家和自动化系统仍然无法解释为什么停工。

下一次实际编码应从一个范围受控的“钢铁—资本品纵向切片”开始，而不是同时改造全部 60 种资源和 91 项活动。

## 2. 现有系统如何演进

| 现有基础 | 可以直接复用 | 必须演进的部分 |
| --- | --- | --- |
| 地点权威库存 | 继续作为资源和资产所有权根节点 | 加入资本品和货运属性；普通舰载插件不进入库存 |
| 实体在途运输 | 保留真实扣货、在途、到达和多跳路径 | 按货运体积占用容量，支持不同运输方式 |
| 100 段建设项目 | 保留渐进消耗和持续建造 | 泛化为设施升级、容量升级、物流和巨构共用项目 |
| 设施等级 | 保留等级、扩建成本和规模效应 | 增加规模阶段、建设时间和资本品需求 |
| 电力、冷却、结构、仓储 | 保留地点限制 | 增加转运吞吐、特殊防护和升级项目 |
| 生产活动 | 保留配方、设施、科技和周期 | 分离产品族与生产方式，允许多条生产线共享产能 |
| 工业模块和插件 | 保留能力门槛与取舍 | 统一纳入生产方式、规模阶段和改造工程 |
| 舰船实体和槽位 | 保留舰船身份、装配、改装和生命周期 | 装配方案按次提交整套普通插件 BOM 和合并工期 |
| 特殊装备实体 | 保留唯一身份和占用关系 | 继续作为普通插件定义之外的例外资产 |
| 科研材料消耗 | 保留逐步消耗与阻塞 | 增加研究耗材、原型和实地测试阶段 |
| 工业模板、后台经济 | 保留地点模板和自动扩建基础 | 扩展为目标产率和有限条件自动化 |
| 巨构阶段 | 保留七阶段、材料流和完成效果 | 复用统一建设系统并增加中途规则效果 |
| 确定性模拟和离线推进 | 继续作为所有长期活动的运行框架 | 增加新资产与项目的确定性边界和守恒测试 |

主要代码演进位置：

- [`data/content.json`](../data/content.json)：新增资本品、生产方式、货运类型、运输方式、设施阶段和科技内容。
- [`src/core/game_state.gd`](../src/core/game_state.gd)：新增建设项目、生产线、物流服务和装配方案工程状态。
- [`src/core/simulation_engine.gd`](../src/core/simulation_engine.gd)：统一项目推进、工业产能分配、生产方式和资产转移。
- [`src/core/logistics_engine.gd`](../src/core/logistics_engine.gd)：按货运体积调度，支持运输方式和服务容量。
- [`src/application/game.gd`](../src/application/game.gd)：提供所有玩家与自动化共用的事务命令。
- [`src/core/content_database.gd`](../src/core/content_database.gd)：校验经济闭环、所有权、解锁、运输兼容和循环依赖。
- [`tests/headless_test.gd`](../tests/headless_test.gd)：加入各阶段规则、守恒和黄金路径测试。

## 3. 第一阶段：全流程验证与统一阻塞原因

> 实施状态：已完成，并由无作弊黄金路径、结构化阻塞诊断和 Guide 回归持续验证。

### 3.1 为什么必须最先完成

增加资本品和生产方式后，一项工程可能同时受到以下条件影响：

- 前置科技。
- 设施和设施规模阶段。
- 资本品。
- 本地原料。
- 其他地点库存。
- 来源保留量。
- 在途货物。
- 路线和运输方式。
- 枢纽装卸能力。
- 电力与散热。
- 仓储。
- 建设能力。
- 维护材料。

如果这些系统继续分别返回自然语言错误，玩家、引导、规划器和自动化都会重复实现阻塞判断，并产生互相矛盾的结论。

### 3.2 统一阻塞代码

首批阻塞代码：

```text
MISSING_TECH
MISSING_FACILITY
MISSING_SCALE_STAGE
MISSING_CAPITAL_GOOD
INPUT_SHORTAGE
INPUT_IN_TRANSIT
ROUTE_UNAVAILABLE
TRANSPORT_MODE_UNAVAILABLE
ROUTE_CONGESTED
HANDLING_CONGESTED
POWER_SHORTAGE
COOLING_SHORTAGE
STORAGE_FULL
MAINTENANCE_SHORTAGE
CONSTRUCTION_CAPACITY_FULL
PROJECT_SLOT_FULL
MANUALLY_PAUSED
```

所有系统返回统一结构：

```json
{
  "status": "BLOCKED",
  "primary_reason": "INPUT_SHORTAGE",
  "location_id": "earth_orbit",
  "item_id": "industrial_machine_tools",
  "required": 8,
  "available": 2,
  "upstream": {
    "reason": "ROUTE_CONGESTED",
    "route_id": "belt_to_lunar"
  }
}
```

统一诊断应由核心层生成，界面只负责翻译和展示。

### 3.3 无作弊黄金路径

建立一个从默认新存档出发的完整自动流程：

- 不直接注入高级资源。
- 不跳过科技。
- 不手工修改区域解锁。
- 不绕过舰船建造和远征。
- 不跳过巨构材料与阶段。
- 最终完成第一次星际远征。

流程记录：

- 每个主目标的完成时间。
- 主要物品收入、支出和峰值库存。
- 生产、物流、研究、建造和远征等待时间。
- 各阶段首要阻塞原因。
- 路线和枢纽最高利用率。
- 舰队损失和维修时间。
- 是否出现不可重复资源依赖。

每个主要阶段保存一份开发场景快照，但黄金路径本身不能使用快照跳关。

### 3.4 正式节奏与测试倍率

把速度倍率集中到模拟配置：

```text
TEST_PROFILE
├─ mining ×10
├─ manufacturing ×10
└─ 其他可按测试需要独立配置

NORMAL_PROFILE
└─ 使用正式平衡参数
```

两种配置使用同一套公式、事务和内容引用，不能在测试模式绕过材料或规则。

### 3.5 完成条件

- 所有持续系统使用统一阻塞结构。
- 新存档能自动走到当前终局。
- 任意失败都能定位到具体命令和阻塞原因。
- 测试与正式速度配置分离。

## 4. 第二阶段：资本品与统一建设队列

> 实施状态：已完成；设施、地点容量、物流容量与巨构使用同一建设队列和渐进材料结算。

### 4.1 泛化建设项目

当前建设项目演进为通用 `ConstructionProject`：

```text
ConstructionProject
├─ FACILITY_BUILD
├─ FACILITY_EXPANSION
├─ SCALE_STAGE_UPGRADE
├─ POWER_UPGRADE
├─ COOLING_UPGRADE
├─ STRUCTURE_UPGRADE
├─ STORAGE_UPGRADE
├─ LOGISTICS_HUB_UPGRADE
├─ TRANSPORT_INFRASTRUCTURE
├─ EXTRACTION_NETWORK
└─ MEGASTRUCTURE
```

每个项目至少保存：

```text
项目 ID
类型
所属地点
目标设施或基础设施
开始等级和目标等级
优先级
项目槽位
总工程量
已完成工程量
材料计划
已交付材料
在途材料
已消耗材料
当前状态
首要阻塞原因
```

### 4.2 地点建设能力

建设能力以地点为主，不是完全共享的全局进度条。

文明级工程协调能力可以提供：

- 跨地点建设上限。
- 工程调度加成。
- 远程施工效率。
- 可同时管理的项目数。

具体项目仍需要目标地点的：

- 本地工程设施。
- 建设能力。
- 资本品。
- 结构、电力和物流条件。

### 4.3 首批资本品

| 资本品 | 主要投入方向 | 主要消耗端 |
| --- | --- | --- |
| 工业机床 | 钢、电子、精密材料 | 冶炼厂、加工厂、装配厂扩建 |
| 自动化核心 | 电子、数据核心、量子组件 | 后台工业、无人采掘、条件自动化 |
| 热交换组件 | 铜、钛、陶瓷或超导材料 | 高能工业、聚变设施、外太阳系基地 |
| 电力总线组件 | 铜、电子、超导材料 | 电厂、船坞和高能工业 |
| 重型结构段 | 钢、钛合金、结构框架 | 大型设施、星港、巨构、大型船体 |
| 精密执行器 | 钢、钴、电子元件 | 采矿设备、模块、装卸和自动装配 |
| 船坞机械 | 机床、重型结构、执行器 | 船厂升级和大型船体生产线 |
| 物流装卸设备 | 机床、执行器、电子元件 | 物流枢纽、货运站、质量投射器 |

最终首轮规模可以扩展到 8–12 种，但每种资本品必须被至少两个持续系统消费。

### 4.4 避免资本品循环软锁

采用分层启动：

- 一级设施继续使用现有建筑框架和设施组件。
- 2–4 级扩建消耗基础机床、结构件和普通材料。
- 5 级规模跃迁开始消耗专用资本品。
- 10 级以后使用高级资本品。
- 永久保留低效、低技术的基础机床恢复配方。
- 资本品生产设施不能把自身唯一恢复配方锁在自身升级之后。

旧存档已有设施等级视为已经完成建设，不追溯扣除新资本品。

### 4.5 事务变化

原有即时操作：

```text
expand_location_industry(location, facility, +5)
```

改为：

```text
queue_facility_expansion(
  location_id,
  facility_id,
  target_level,
  priority
)
```

完成项目后才修改设施等级。取消项目必须明确处理未消耗、已交付和在途物资。

### 4.6 完成条件

- 所有设施和容量升级进入建设队列。
- 多个工程真实竞争有限建设能力。
- 工程按进度消耗材料。
- 资本品形成可重复、无循环软锁的生产链。
- 巨构与普通扩建争夺同一类核心建设资源。

## 5. 第三阶段：多生产线、生产方式和工业规模

> 实施状态：进行中；共享产能、产线优先级、四级规模阶段、四类地点专精，以及钢铁与大型结构的替代生产方式已经落地。电子与自动化、能源与散热、舰船与物流设备三条纵向链仍按 5.7 的顺序后续展开。

### 5.1 当前结构需要解决的问题

当前模式更接近“一个设施运行一个活动”。这不足以支持：

- 同一大型工业综合体同时生产多个产品。
- 目标产率分配。
- 产品优先级。
- 多生产方式比较。
- 设施规模阶段。
- 自动化重新分配产能。

### 5.2 目标产业状态

每个地点设施拥有总产能，多条生产线共享：

```text
轨道铸造厂
├─ 等级：12
├─ 规模阶段：工业综合体
├─ 总产能：120
├─ 钢铁：50% 产能
├─ 钛合金：30% 产能
└─ 重型结构段：20% 产能
```

生产线状态：

```text
line_id
product_family_id
method_id
capacity_allocation
priority
cycle_progress
input_commitments
fractional_materials
theoretical_rate
actual_rate
status
blocked_reason
```

### 5.3 生产方式定义

生产方式与产品族分离：

```text
产品族：钢铁
├─ 常规炉法
├─ 电弧冶炼
└─ 真空高纯冶炼
```

每种方式定义：

- 输入和产出。
- 副产物和废料。
- 工程量或周期时间。
- 材料利用率。
- 能源需求。
- 散热需求。
- 维护需求。
- 货运体积变化。
- 设施和规模阶段要求。
- 科技与模块要求。
- 环境适用性。

### 5.4 统一产率公式

```text
有效产能
= 设施基础能力
× 分配等级
× 规模效应
× 供电覆盖
× 散热覆盖
× 维护覆盖
× 熟练度与专业度
× 生产方式修正
× 地点专精修正
```

最终实际产率继续受到以下硬限制：

- 本地输入库存。
- 本地内部转运吞吐。
- 输出仓储空间。
- 特殊防护和环境要求。

### 5.5 工业规模阶段

| 等级 | 阶段 | 规则变化 |
| --- | --- | --- |
| 1–4 | 工坊 | 单一基础生产方式、人工操作为主 |
| 5–9 | 工厂 | 开放替代工艺和初级模板 |
| 10–19 | 工业综合体 | 多产线、更多模块、地点专精和规模效应 |
| 20+ | 自动化工业区 | 后台生产、高级方法和政策自动化 |

跨阶段必须通过建设项目完成，不能达到等级后自动瞬时变化。

### 5.6 地点专精

首轮四类：

1. 大宗冶炼中心。
2. 精密制造中心。
3. 燃料与低温工业中心。
4. 舰船制造中心。

后续再增加物流转运和科研特殊材料专精。

专精切换需要：

- 建设时间。
- 改造工程。
- 资本品。
- 生产停机或效率损失。

### 5.7 内容落地顺序

不一次重写全部活动，依次完成四条纵向链：

1. 钢铁与大型结构。
2. 电子与自动化。
3. 能源与散热。
4. 舰船、维修与物流设备。

### 5.8 完成条件

- 一个设施能够合理分配多条生产线。
- 每条重点产业链至少存在两种有意义的方法。
- 方法至少改变三类实际约束。
- 地点专精影响合理布局，而不只是提供通用加成。
- 工业规模阶段带来能力质变。

## 6. 第四阶段：货运属性、运输方式和物流服务

> 实施状态：两轮均已完成；六类货运属性、通用货运/大宗拖船/质量投射器/低温运输舰/高速快运舰五种方式、实体舰船分配、综合路径评分、来源/航线锁定、结构化物流阻塞和存档迁移均已落地。

### 6.1 物品货运属性

每种可运输物品增加：

```json
{
  "freight_class": "BULK",
  "freight_units": 4.0
}
```

首批货运类型：

```text
BULK
STANDARD
PRECISION
CRYOGENIC
HAZARDOUS
OVERSIZED
```

运输容量占用：

```text
货运容量占用
= 物品数量
× 单位货运体积
× 运输方式适配修正
```

### 6.2 生产改变货运体积

示例关系：

```text
100 单位混合原矿 → 400 货运体积
40 单位精矿      → 较低货运体积
20 单位合金      → 更低货运体积
4 单位精密组件   → 少量高价值货运体积
```

具体数值在平衡阶段调整，但必须保留“初加工减少大宗运输压力”的关系。

### 6.3 运输方式定义

每种运输方式定义：

- 支持货运类型。
- 基础容量。
- 航行速度。
- 装卸速度。
- 推进剂消耗。
- 能源消耗。
- 维护消耗。
- 所需设施和科技。
- 可用路线和方向。

首批建议先做：

1. 通用货运舰。
2. 大宗拖船。
3. 质量投射器。

第二轮加入：

4. 低温运输舰。
5. 高速快运舰。

### 6.4 物流服务

玩家不逐艘运输货物，而是把运输资产配置给路线服务：

```text
地球—月球通用物流服务
├─ 运输方式：通用货运
├─ 分配舰船：3
├─ 每分钟容量：120
├─ 支持货类：STANDARD / PRECISION
├─ 当前利用率：87%
└─ 优先级策略：科研组件 > 维修补给 > 普通材料
```

运输调度器继续自动生成实际批次。舰船分配只改变可用容量、成本和适用货类。

质量投射器等基础设施也提供物流服务，但不占用舰船。

### 6.5 路径选择

运输路径不能只比较时间，应在满足货类要求后比较综合成本：

```text
运输时间
+ 容量拥堵
+ 装卸时间
+ 推进剂
+ 能源
+ 维护
+ 转运次数
+ 特殊货物风险
```

玩家仍可锁定来源和路线，自动选择只负责默认调度。

### 6.6 完成条件

- 大宗原矿与精密组件占用不同运力。
- 至少三种运输方式有不同适用场景。
- 运输舰是实际分配的舰船资产。
- 远端粗加工可以显著缓解路线拥堵。
- 物流守恒仍覆盖来源、在途、项目和目标库存。

## 7. 第五阶段：装配方案与舰船工业

> 实施状态：已完成；普通舰载插件是装配方案中的定义，不是库存资产。应用方案时一次性投入整套普通插件的制造资源，并用一个合并工程结算制造与安装工期；首批五类后勤与工业角色已由装配插件接入实际系统效果，舰型本身不授予任务能力。

### 7.1 普通插件的表示

普通插件只存在于装配方案和当前舰船配置中：

```text
装配方案
├─ 武器：轻型机关炮
├─ 防御：民用护盾
├─ 推进：基础推进器
└─ 功能：货舱扩展
```

普通插件没有库存数量、运输货物、项目暂存实体或独立 UUID。舰船上的插件 ID 表示当前配置，不表示可拆卸资产。特殊掉落装备继续保持独立 ID、来源和唯一占用关系。

### 7.2 应用装配方案

每次应用方案都执行完整装配订单：

```text
选择装配方案
→ 校验插件设计、槽位和装配预算
→ 一次性扣除整套普通插件 BOM
→ 制造插件
→ 安装并完成配置
```

即使新旧方案包含相同的普通插件，也不会抵扣材料。旧普通插件拆除后直接退出模型，不进入地点库存，也不能运输或复用。

### 7.3 制造与安装工期

概念上装配包含两段时间：

1. 按方案制造全部普通插件。
2. 在星港完成拆卸、安装和联调。

当前版本暂时合并为一个连续改装工程，但分别记录制造时间与安装时间，便于未来拆成两阶段。项目开始时即提交全部材料；取消项目可以恢复原装配，但已经投入的材料不返还。

### 7.4 造船流程

造船计划的 `starting_modules` 是初始装配方案。它们的原料 BOM 直接合并进整舰建造成本，并随船体工程渐进消耗；船厂不要求预先制造或暂存模块成品。

船体完工时直接得到指定初始配置，不生成中间模块库存。

### 7.5 旧存档迁移

迁移必须保证：

- 当前舰船装配不变化。
- 旧版普通模块库存按原 BOM 转回同地点原料。
- 在途普通模块按原 BOM 转为同一批在途原料。
- 旧造船模块暂存转回项目地点原料，并保留船体进度。
- 进行中的改装保留目标方案、已投入价值和进度，不生成模块库存。
- 特殊装备 ID 和唯一占用保持不变。

### 7.6 首批后勤与工业装配

1. 大宗货运阵列：授予大宗/超限货运能力和额外货舱。
2. 低温货舱系统：授予低温/危险品运输能力和额外货舱。
3. 移动维修系统：授予舰队维修支援能力。
4. 建设支援系统：授予移动工程能力。
5. 深空勘测系统：授予深空勘测和远程扫描能力。

阿特拉斯、北辰、仁慈号、代达罗斯和远望号是槽位与工程预算不同的舰体型号。舰船开发科研只解锁对应造船计划；建成时的初始方案可以让它们立即承担推荐职责，但职责始终来自当前装配。拆除角色插件后，哪怕舰型名称不变，也不再提供相应物流、维修、建设或勘测效果；相容的其他舰体安装同一插件后可以承担该职责。

货运装配提供共享路线或舰队容量，不引入逐舰拖放货物。

### 7.7 完成条件

- 普通插件不能作为库存或货物生产、运输和暂存。
- 每次应用装配方案都一次性扣除整套普通插件 BOM，而不是只扣新旧差额。
- 拆下的普通插件不返还地点库存；取消项目不返还已投入材料。
- 船厂把初始装配 BOM 纳入整舰成本，不生成普通模块实体。
- 制造与安装当前使用一次合并工期，并保留未来拆分所需字段。
- 舰体定义不携带任务能力；科研开发只解锁舰型造船计划。
- 后勤插件实际改变物流、维修、建设或勘测能力，换装会同步改变舰船职责。

## 8. 第六阶段：技术代际与研发项目

> 实施状态：已完成首轮系统化实现；八个技术能力域、流量型研究能力、多阶段研发项目、四类工程门槛、实验技术成熟度、技术外溢、可补研路线、真实原型/实地测试和工业改造项目均已接入现有工业闭环。

### 8.1 核心目标

科技系统不采用单纯的“积累科研点 → 点击科技 → 解锁配方”模式。

研发应直接作用于现有工业体系，并持续向玩家提出新的材料、制造、能源、设施和物流需求。

核心循环：

```text
现有技术与工业能力
→ 启动研发项目
→ 理论研究
→ 暴露新的工程瓶颈
→ 获得实验性材料 / 工艺 / 部件
→ 建立对应生产与实验能力
→ 制造原型
→ 实际测试
→ 技术成熟
→ 改变已有产业体系
→ 为下一代研发提供基础
```

研发不是独立于工业系统之外的一种资源消耗，而是整个工业体系的一种长期负载和升级驱动力。

### 8.2 技术能力域

不建立包含大量细碎节点的传统科技树。

文明拥有若干长期积累的技术能力域，例如：

- Materials Science：材料科学。
- Manufacturing：制造与加工。
- Energy：能源工程。
- Propulsion：推进技术。
- Automation & Computing：自动化与计算。
- Ship Engineering：舰船工程。
- Logistics：物流与运输。
- Anomaly Science：异常现象研究。

技术能力域用于描述文明已经掌握的基础知识和工程能力。

不同研发项目会：

- 要求一定能力水平；
- 提升相关能力；
- 产生新的专业技术；
- 因已有技术积累而降低后续项目难度。

技术进步因此形成互相复用的技术网络，而不是单向线性的科技树。

### 8.3 研发项目

真正需要玩家主动管理的核心研发内容采用 **R&D Program / 研发项目**。

完整游戏只需要数十个重要研发项目，而不是数百个等价科技节点。

例如：

- 新型采矿舰计划。
- 聚变能源计划。
- 质量投射器计划。
- 自动采掘网络。
- 大型舰体工程。
- 深空推进计划。
- 轨道制造计划。
- 星际引擎计划。
- 异常物质应用计划。

研发项目代表文明试图突破当前工业能力边界的一项大型工程。

项目本身不是固定材料换取固定进度，而是一系列逐步推进的工程阶段。

### 8.4 项目阶段与工程门槛

只有重要技术使用完整的多阶段研发流程。

标准结构：

```text
理论研究
→ 实验验证
→ 工程开发
→ 原型制造
→ 实地测试
→ 工业化
```

不同项目可以省略部分阶段，不要求所有研发都使用完全相同的流程。

项目推进过程中可以出现四类主要门槛：

#### Knowledge Gate

要求一定的科研和工程能力。

例如：

- Materials Science ≥ 3。
- Propulsion Engineering ≥ 2。
- Computing Capacity ≥ 50。

#### Material / Component Gate

要求玩家制造项目中新研发出的材料、实验组件或原型部件。

例如：

- 实验级超导材料。
- 高温陶瓷。
- 原型推进室。
- 高场磁体。
- 实验控制核心。

#### Infrastructure Gate

要求建设或扩充真实科研和测试基础设施。

例如：

- 高能实验室。
- 真空测试设施。
- 材料实验中心。
- 大型工程测试场。
- 轨道试验船坞。

#### Operating Condition Gate

要求整个工业体系达到某种运行条件。

例如：

- 足够的持续电力。
- 足够的峰值供电能力。
- 足够的冷却能力。
- 足够的轨道物流吞吐。
- 足够的精密制造能力。

研发因此会主动制造新的工业瓶颈，促使玩家扩张或重组自己的经济体系。

### 8.5 实验技术与工业化

研发过程中获得的新技术不必立即成为成熟量产技术。

新材料和新工艺可以经历：

```text
理论发现
→ 实验室样品
→ 实验级生产
→ 中试生产
→ 工业量产
```

例如，一个聚变项目可能首先获得实验级超导材料。

早期版本：

- 成本极高；
- 产量很低；
- 只能由高级实验设施制造；
- 主要用于项目本身。

随着后续研发和工业化，其生产方式逐渐成熟，最终成为可以进入正常工业体系的标准材料。

因此科技不会在“研究完成”的瞬间凭空变成工业能力。

### 8.6 技术外溢

大型研发项目除了最终目标之外，可以产生与项目工程问题直接相关的 **Spillover Technologies / 技术外溢成果**。

例如聚变能源计划可能产生：

- 高场超导材料。
- 低温工程。
- 高温陶瓷。
- 精密线圈制造。
- 高功率热管理。
- 等离子体控制。

这些成果必须能够继续用于其他工业系统和研发项目。

例如：

```text
聚变计划
→ 高场超导技术
→ 质量投射器研发成本下降
→ 高级电动推进器获得新生产方式
→ 舰船能源系统获得新模块
```

技术外溢必须来源于项目实际需要解决的工程问题，不能作为无关的随机奖励。

一个项目的主要价值不仅是最终解锁的设备，还包括它为整个技术体系留下的可复用能力。

### 8.7 研究消耗

不设置能够脱离工业体系独立大量生产的通用“科研货币”。

研发主要消耗三类能力和资源：

#### Research Capacity

表示科学家、计算能力、实验能力和工程人员形成的研究吞吐。

属于流量，不作为库存积累。

#### Industrial Supply

研究持续占用真实工业产品，例如：

- 高级电子元件。
- 精密机械。
- 特种合金。
- 推进剂。
- 能源。
- 冷却剂。

这些资源必须来自正常工业体系。

#### Experimental Articles

项目特有的实验材料、测试组件和原型设备。

例如：

- 材料实验组件。
- 推进测试组件。
- 舰船原型组件。
- 异常物质样本。

标准化研究耗材可以存在，但只能作为科研活动的辅助消耗，不能成为另一套与工业脱离的“科研瓶”。

### 8.8 原型与实地测试

关键技术的原型必须是真实工业产物。

例如：

```text
研发新型采矿舰
→ 制造实验采矿模块
→ 制造原型舰
→ 派往真实矿区
→ 完成规定采掘任务
→ 收集运行数据
→ 完成工程验证
→ 开放量产型号
```

实地测试应尽量调用现有游戏系统：

- 舰船。
- 设施。
- 物流任务。
- 能源网络。
- 采矿系统。
- 生产系统。
- 深空探索。

测试不应表现为单纯等待倒计时。

### 8.9 技术效果

`UNLOCK / METHOD / SYSTEM` 不再表示互斥科技类型，而是技术成果可能具有的效果标签。

#### UNLOCK

开放新的实体或地点：

- 设施。
- 模块。
- 船体。
- 舰船部件。
- 地点。
- 运输方式。

#### METHOD

开放新的生产方法。

同一种产品可以因为技术发展出现新的制造路线，并在：

- 原料。
- 能源。
- 资本设备。
- 吞吐量。
- 产品质量。
- 地点要求。

之间形成不同 trade-off。

#### SYSTEM

开放新的工业组织方式，例如：

- 中心化工业。
- 分布式工业。
- 大规模吞吐。
- 精密制造体系。
- 舰队工业化。
- 自动采掘网络。

SYSTEM 技术只代表文明已经掌握这种组织能力。

真正采用新的工业体系仍必须启动 Industrial Transformation Project，消耗：

- 资本品。
- 建设能力。
- 改造时间。
- 停机时间。

体系允许重新调整，不设置不可恢复的永久错误选择。

### 8.10 项目路线与技术积累

部分大型项目可以存在不同工程路线，例如：

```text
深空推进计划

高推力路线
→ 高温材料
→ 强化冷却
→ 大型推进室

高效率路线
→ 精密制造
→ 高级控制
→ 电磁约束
```

不同路线产生不同技术外溢，并改变最终设备特性。

路线原则上不是永久互斥。

玩家以后可以继续补充另一条技术路线，但需要额外投入。

已有技术积累应降低相关项目后续成本、缩短阶段或改变解决方案，而不是仅提供统一的百分比科研加成。

### 8.11 设计约束

研发项目必须遵守以下原则：

- 一个大型项目通常只包含 3–5 个具有实际意义的主要阶段。
- 每个阶段最多突出一个主要新瓶颈，避免形成任务清单式俄罗斯套娃。
- 玩家在启动项目时能够看到大致研发路线和未来可能需要的能力。
- 项目可以产生新的工程问题，但不能用完全不可预见的巨额需求偷袭玩家。
- 新研发的材料、设施和工业能力完成项目后仍应继续有价值。
- 研发过程中建设的工业体系原则上不能成为一次性废弃内容。
- 技术外溢必须能够影响其他项目或现有产业。
- 新科技应创造新的产业选择和新的优化问题，而不仅仅提供数值升级。
- 重要技术应该改变已有生产、能源、物流、舰船或工业组织方式。
- 不要求所有小型改进都成为独立研发项目。

### 8.12 第六阶段完成标准

第六阶段完成后，玩家应第一次形成完整的：

```text
科研
↕
材料
↕
制造
↕
能源
↕
物流
↕
设施
↕
舰船
```

闭环。

玩家面对一个重要研发项目时，不再只是问：

> “还需要多少科研点？”

而会开始问：

> “我缺什么能力？”
>
> “这个新材料在哪里生产？”
>
> “现有精密制造能力够不够？”
>
> “为了测试它，我是不是需要扩建电网？”
>
> “原型应该在哪里制造？”
>
> “完成这个项目以后，这套新工业能力还能用来做什么？”

第六阶段的最终目标不是建立一棵科技树，而是建立一个能够持续向已有工业系统产生新需求、新能力和新组合方式的 **Technology Network + R&D Program System**。

## 9. 第七阶段：库存驱动生产、产能规划与条件自动化

> 实施状态：完成（1.27.0 / Save Schema 33）。本节覆盖第三阶段遗留的“产能百分比分配、地点职业加成、后台抽象生产池”设计；这些旧机制只保留存档兼容数据，不再参与运行。

### 9.1 真实生产与库存

生产链固定为：

```text
资源禀赋 → 原材料开采 → Factory → Production Device
→ Production Method → 实际产品 → Location Inventory
→ 运营 / 项目 / 建造 / 舰船 / 出口消耗
```

不存在可在产品之间转换的星球生产力池。每条运行产线必须解析到真实 Factory、已安装装置和生产方式，实际消耗输入、电力、冷却与物流能力。一个 Factory 的多条运行产线自动共享设备吞吐；玩家不设置逐线生产百分比。

库存按 `BULK / COMPONENT / FLUID / SPECIAL` 四类仓储限制容量。每个商品有数据驱动的仓储类别和单位体积。生产事务在写入前检查对应类别：满仓进入 `BLOCKED_OUTPUT`，空间恢复后自动继续。仓储容量是设施，不是无限数字，也不是每商品目标值。

### 9.2 统一 Demand Registry 与 O&M

所有需求登记为可追踪来源：

```text
productId
quantity 或 rate
sourceType / sourceId
locationId
priority
startTime / completion condition
```

首版接入：

- `maintenance`：设施按类型、运行状态和利用率消耗共享维护品。
- `fleet_operation`：舰船和舰队运营消耗。
- `construction`：建设项目剩余承诺。
- `research_project`：当前研发阶段材料与实验件承诺。
- `shipbuilding`：造船订单剩余材料承诺。

维护品来自正常工业库存，不存在维护点。缺少维护会降低真实设备运行覆盖率，不会凭空扣一个全局效率 Buff。

### 9.3 Current Economy Analysis

系统按地点、商品自动计算：

```text
On Hand / Storage Capacity / Free Storage
Production / Consumption / Import / Export / Net Rate
Continuous Demand / Committed Demand
Stock Coverage / Blocked Sources / Demand Sources
```

状态由运行数据诊断为 `STABLE / TIGHT / CRITICAL / SURPLUS / STORAGE_FULL`。工业 UI 先显示仓储、电力和物流总况，再列出真正有库存流、承诺需求或阻塞的商品。玩家可从短缺产品沿 Production Method、输入、Factory 或基础设施追踪最短瓶颈链。

### 9.4 Production Dependency Graph

Content Database 生成 Product、Production Method、Factory、Production Device 和 Infrastructure Requirement 节点以及 consumes、produces、requires、supports 边。首版求解 DAG；回收和循环链作为 `External Credit`，不阻断普通 BOM 展开。Runtime、Planner 和 UI 调用同一套产率与资源公式。

### 9.5 只读目标产能规划器

玩家输入最终产品的目标单位/小时，规划器输出：

- 最终品、中间品与原始资源需求。
- 当前、建议和缺口的真实 Factory 数量/等级。
- 所需 Production Device 与 Production Method。
- 电力、冷却、四类仓储和建设资本品。
- 需要跨地点补给的物料流与潜在拥堵。
- 当前实际产率、首要瓶颈和最短瓶颈链。

规划器只读。它不建设、不拆除、不改玩家锁定配方、不重做路线。预测不会使用 Simulation 无法执行的规则。

### 9.6 工厂控制与有限自动化

单一工艺设施在有输入、供电和输出空间时自动运行；真实状态包括 `RUNNING / BLOCKED_INPUT / BLOCKED_OUTPUT / POWER_LIMITED / LOGISTICS_LIMITED / PAUSED`。首版默认 `PINNED`，允许玩家关闭，并保留 Compatible Recipe Group 数据供后续 `AUTO` 切换。

条件自动化仅允许预授权动作：

- Pause / Resume Factory。
- Adjust Route Cargo Policy。
- Adjust Project Priority。

规则调用正常事务，尊重 Manual Lock，记录条件、原因、执行前后值，支持暂停、撤销、冷却和 hysteresis。自动扩建未开放；旧工业模板不能排队扩厂。

### 9.7 明确不做

首版不实现 AI 全产业建设、自动专业化、每商品安全库存、每商品生产百分比、抽象 Production Capacity Pool、循环工业精确求解、动态市场、全星系最优布局和大规模 Recipe 自动切换。一个地点只要具备真实设备、能源、仓储、物流和原料，就可以建立完整工业体系。

### 9.8 完成验收

- 真实 Factory + Device + Method 才能产出，旧后台容量不再产出。
- 四类仓储分别限制库存，满仓停机并可恢复。
- O&M、建设、研发和造船需求可以追溯来源。
- 玩家不需要逐商品库存阈值或逐线百分比。
- UI 显示库存、实际生产/消费/净流、承诺和阻塞。
- 依赖图、只读规划与最短瓶颈链可查询。
- Planner 不修改状态且与 Simulation 共用计算入口。
- 有限自动化不绕过资源、建设、物流、仓储和手工锁定。
- 地点专业化是经济结果，不是硬编码职业或商品数量限制。

## 10. 第八阶段：勘测、区位条件与工业地理

> 实施状态：完成（1.28.0 / Save Schema 34）。当前范围严格为单一 `sol` 恒星系；旧四巨构和星际入口在本阶段冻结，未为未来跨恒星内容增加专用抽象。

### 10.1 Location Environment

所有可开发地点统一持有：

```text
gravity / vacuum / atmosphere / solarFlux
thermalEnvironment / radiation
transportDistance / constructionDifficulty
maintenanceSeverity
```

Production Method、Extraction Method、O&M、Construction、Logistics 和 Planner 读取同一份环境数据。区域没有 `Mining +20%` 之类无条件 Buff。

### 10.2 Survey State 与信息访问

统一顺序为：

```text
UNKNOWN → DETECTED → SURVEYED → DEEP_SURVEYED
```

* `UNKNOWN`：只公开地点身份。
* `DETECTED`：只公开资源类别、潜力区间、显著辐射、距离和建设难度区间。
* `SURVEYED`：公开品位范围、可持续潜力、副产物、允许工法和完整环境，允许永久开发。
* `DEEP_SURVEYED`：公开精确品位和当前技术可达到的高级潜力；不是强制步骤。

UI 与领域接口均调用 `location_intelligence()`，低勘测状态不会读取并显示内容数据库中的隐藏精确值。

### 10.3 真实 Survey Mission

勘测任务保存并结算：

```text
origin / target / targetState
assignedShipIds / surveyCapability
duration / progress / real costs
```

它要求停泊、正常、装有相应传感器或深度勘测插件的实体舰船，并消耗正常库存中的推进剂、维修材料和电子元件。任务进入在线与离线模拟边界，不存在 Survey Point 货币。

### 10.4 Resource Profile 与 Sustainable Extraction Potential

每个资源地点数据驱动声明：

```text
resourceType / gradeRange / byproducts / allowedMethods
base extractionPotential
```

移动采矿的已安装开采力会被地点潜力硬上限截断。固定和高级工法通过 multiplier 改变可长期支持的规模。状态中没有 Remaining Ore、枯竭计时器或自动迁移。

### 10.5 Site Development

永久开发流程为：

```text
SURVEYED
→ 选择兼容 Extraction Method
→ SITE_DEVELOPMENT Construction Project
→ 使用地点库存渐进投入资本品
→ 检查本地 Power / Bulk Storage / Logistics
→ Permanent Extraction Site
```

开发项目复用普通建设队列、优先级、材料承诺、远端库存和存档；没有第二套建设资源。远端建设资源承诺已修正为读取项目自身 Location，而不是错误读取 Main Base。

### 10.6 工法、维护与物流区位

Production / Extraction Method 使用可扩展环境条件数组，不依赖大量地区 `if/else`。例如真空电弧炼钢在非真空木星环境会被真实阻塞；大气采集要求适合的大气类型。

地点维护严重度会放大正常 O&M Demand Source：辐射主要增加电子维护，热循环和机械环境提高结构/机械维护。远端压力来自多段物流路线的真实 transit time、运输能力、燃料与维护，不存在抽象“自治加成”。

### 10.7 Planner 集成

只读 Planner 额外输出 `industrial_geography`：目标原料吞吐、已勘测地点潜力、当前工法、总可持续能力、短缺和候选解法。候选解法只提示追加勘测、深度勘测或研究/采用高级工法；不会自动创建舰队、开发地点或修改物流。生产方式选择也会过滤与目标地点环境不兼容的方法。

### 10.8 完成验收

* 所有 Location 属于同一 `sol` 系统并持有统一环境参数。
* 四级 Survey State 真实限制情报，且任务占用实体舰船与正常物资。
* 普通资源点永久存在，以 Sustainable Extraction Potential 限制规模。
* Surveyed Site 通过正常 Construction、Inventory、Energy、Storage 和 Logistics 开发。
* 环境改变工法可用性与实际 O&M，而不是提供纯百分比区域 Buff。
* 多跳 transit time 让外层区域产生更长补给周期。
* 新工法能提高已经开发过的旧地点价值。
* Planner 能计算已勘测潜力短缺且保持只读。
* 地点没有商品种类或职业硬限制；综合工业世界仍然合法。
* 旧巨构入口在本阶段冻结，跨恒星内容未进入实现范围。

## 12. 存档和迁移策略

每个能够独立合并的状态改造都必须有明确存档迁移，不能等所有系统完成后一次迁移。

推荐顺序：

1. 增加通用建设项目并迁移当前建设队列。
2. 增加多生产线并迁移现有工业操作。
3. 增加货运属性，不改变旧货物数量。
4. 增加物流服务并迁移当前路线基础容量。
5. 增加整套装配制造事务，并迁移旧模块库存与进行中的改装。
6. 增加规划器和自动化授权状态。

迁移原则：

- 现有资源数量不凭空减少。
- 已有设施等级不被回退。
- 已完成的当前装配不要求玩家重新制造；下次主动应用方案时按新规则投入整套 BOM。
- 在途货物保持来源和目标。
- 正在进行的研究、建设、造船、改装和远征尽量保持进度。
- 无法无损迁移时必须明确版本策略，不能静默丢弃状态。

## 13. 必须持续验证的逻辑不变量

### 13.1 资产所有权

任意资源或资产只能处于一个位置：

```text
地点库存
运输中
项目暂存
舰船安装
已消耗或损失
```

### 13.2 数量守恒

- 运输前后总量守恒。
- 项目取消不会复制材料。
- 普通插件拆装不会生成库存；特殊装备仍保持唯一占用。
- 报废回收只产生规则允许的回收量。
- 战斗损失明确记录为损失或残骸。

### 13.3 模拟一致性

- 一次离线推进一小时与分段推进一小时结果在允许误差内一致。
- 速度倍率不改变配方比例和资产守恒。
- 自动化和手工操作使用相同事务。

### 13.4 经济闭环

- 每个战略消耗品有确定性来源。
- 每个资本品至少有两个持续消耗端。
- 每个新中间物至少创造一种实际决策。
- 开局和迁移存档保留低效恢复路线。

### 13.5 可解释性

- 每个阻塞项目都有结构化首要原因。
- 根因可以追溯到上游资源、设施、能源或物流。
- 规划器和模拟器使用同一套生产与需求公式。

## 14. 不采用的实现方式

- 不先往内容配置中批量添加几十种资源，再补规则。
- 不为标准量产模块全部生成独立 UUID；只有特殊模块保留独立身份。
- 不用抽象市场准入率替代真实物流。
- 不让自动化直接修改状态或免费创建项目。
- 不让地点专精退化为无条件的通用产量加成。
- 不把设施 1–30 级做成同一个百分比连续增长。
- 不把关键生产方式做成无代价的高级版本。
- 不在诊断、警报和重规划完成前加入全面资源枯竭。
- 不在太阳系工业深化完成前开发第二恒星系。
- 不引入人口、市场、政治、逐机器布局或即时战术微操。

## 16. 工业深化逻辑完成标准

只有同时满足下列条件，才可以开始第二恒星系：

1. 新存档能够无作弊完成第一次星际远征。
2. 任意核心停工状态可以追溯到具体根因。
3. 所有设施升级都进入统一建设队列。
4. 资本品持续限制工业扩张，而不造成循环软锁。
5. 四条重点产业链都存在有意义的生产方式选择。
6. 地点容量和专精能改变合理工业布局。
7. 至少三种运输方式拥有不同适用场景。
8. 远端粗加工与中心精炼在不同条件下都可能合理。
9. 普通插件不进入库存或运输；每次应用方案完整消耗 BOM，拆卸不返还成品。
10. 五类工业/后勤角色插件能够通过当前装配连接物流、建设、维修和勘测；舰型本身不授予这些效果。
11. 目标产率规划器能解释设施、原料、能源和物流缺口。
12. 后期操作能够从逐条启动生产转向目标、警报和例外管理。
13. 科技能改变工业组织方式，而不只是解锁更高材料。
14. 巨构工程和普通工业扩张真实争夺建设能力。
15. 存档迁移、离线推进和自动化不破坏资产守恒。

## 17. 最终结论

从逻辑和核心内容出发，实现目标的关键不是增加更多系统，而是让现有系统形成更强的约束关系：

> **地点决定能够建设什么；  
> 生产方式决定如何使用资源；  
> 货运成本决定在哪里加工；  
> 资本品和建设能力决定扩张速度；  
> 技术代际决定工业如何重新组织；  
> 实体舰船把工业能力转化为前沿行动；  
> 自动化把不断扩大的网络提升到文明管理尺度。**

首个实际实现目标应是钢铁—资本品纵向切片。完成后，玩家会第一次真实面对：

> 应该在小行星带粗加工以节省运力，还是把原矿送回高效中心；应该先扩建铸造厂提高资本品产能，还是先扩建物流枢纽解决拥堵。

当这个选择能够由真实库存、产能、能源、建设和运输共同得出，并被测试完整验证时，项目就迈入了正式的工业深化阶段。
