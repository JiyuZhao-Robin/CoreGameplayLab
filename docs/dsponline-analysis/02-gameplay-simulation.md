# DSPONLINE 游戏逻辑与模拟

## 1. 游戏模型

DSPONLINE 的核心不是角色移动，而是一个可编辑的工业网络：

```text
银河生成与探索
  -> 行星资源与环境
  -> 采矿 / 轨道采集
  -> 传送带 / 托盘 / 物流站
  -> 配方生产与增产
  -> 电力与燃料
  -> 科研与解锁
  -> 建设施工与蓝图
  -> 星系空间站 / 量子物流
  -> 戴森云与戴森球
  -> 银河出口、活动、排行榜和终局
```

普通模式和速度跑模式共用绝大多数状态结构，但保存槽、云存档、计时和排行榜约束分开。

## 2. 内容模型

`src/game/content.ts` 是内置目录：

- `PLANETS` / `STAR_SYSTEMS`：静态名称、类别与关系。
- `ITEMS`：78 个矿物、材料、组件、矩阵、燃料、建筑物品和终局资源。
- `BUILDINGS`：39 个采集、制造、电力、物流、研究和巨构相关建筑。
- `RECIPES`：80 个配方，声明设备、周期、输入、输出和科技要求。
- `CONSTRUCTION`：建筑、线路、分拣器等施工成本。
- `TECHNOLOGIES`：76 个科技节点，包含矩阵成本、层级、前置和解锁。
- `FUEL_ENERGY_MJ`：燃料能量表。

内容验证不仅检查 key 是否存在，还检查配方引用、建筑兼容、科技闭包、施工来源和已废弃科技。`contentPacks.ts` 会把扩展内容按依赖顺序注册到运行时目录，并用 fingerprint 绑定 Worker。

## 3. GameState

`src/game/types.ts:1634-1693` 的 `GameState` 是领域真相。主要子聚合如下：

| 子聚合 | 作用 |
| --- | --- |
| `entities` | 矿脉、机器、电力设施、仓储、分流器、物流站等 |
| `belts` | 源、目标、物品、端口、等级、并联数、优先级、堆叠、路径和累计转运 |
| `tray` / `planetTrays` | 当前行星与其他行星的玩家物资托盘 |
| `planetMetrics` / `powerGridMetrics` | 发电、需求、功率因数、储能、燃料和吞吐快照 |
| `research` | 当前、暂停、队列、有限科技与无限科研 |
| `constructionQueue` | 蓝图部署等待材料、等待舰队与建设状态 |
| `constructionAutomation` | 制造中心目标、任务 WIP、轮询和累计产出 |
| `galaxy` / `exploration` | seed、行星环境、命名、角色、解锁和任务 |
| `dysonSwarm` / `dysonSphere` / `dysonEngineering` | 轨道、帆、节点、框架、壳层和发电 |
| `systemSpaceStations` / `orbitalStation` | 星系空间站与轨道空间站进度、模块、合同和装饰 |
| `quantumLogisticsNetwork` | 量子库存、容量、接入和结算信息 |
| `endgame` | 银河出口、黑洞、活动和终局指标 |
| `timeWarp` / `idleSettlement` | 时间扭曲控制、待结算债务和纯挂机收益 |
| `blueprints` / `canvasRegions` / `canvasBookmarks` | 玩家工厂布局资产 |
| `campaign` / `achievements` / `speedrun` | 引导、成就和竞速约束 |

状态中的数量在 v47 以非负安全整数为主；研究、银河出口等极大计数通过十进制字符串和 BigInt 边界处理，避免 JSON 丢精度。

## 4. 每个模拟步的严格顺序

源码的单核 `simulateStep()` 与多核的 `prepareSimulationStep()` / `runPlanetSimulationPhase()` / `completeSimulationStep()` 保持等价。

### 4.1 全局前置阶段

`engine.ts:6279-6330`

1. 计算本步结束时间和跨过的 5 秒系统枢纽边界。
2. 刷新时间扭曲控制。
3. 确保动态物流航线索引有效。
4. 推进探索任务。
5. 推进手工制造队列。
6. 吸收戴森帆并衰减戴森云。
7. 重置物流站本步运行时字段。
8. 将物流缓冲写回目标库存。
9. 执行输入侧传送带转运。
10. 为本步生产输出预留传送带目标容量。
11. 运行轨道采集器。
12. 排空物资配送枢纽。
13. 计算各恒星系戴森接收功率。

先传输已有输入，再预留本步输出空间，解决了大堆叠机器因输出缓存瞬时满而错误停机的问题。

### 4.2 行星局部阶段

`engine.ts:6163-6276`

每颗行星按以下顺序运行：

1. 按 `POWER_GRID_IDS` 计算电网供需和分配。
2. 执行燃料消耗、储能充放电等电力设施行为。
3. 运行矿机。
4. 运行配方机器。
5. 运行建筑制造中心。
6. 运行射线接收站。
7. 更新行星与各电网指标。
8. 输出本行星实体、指标、产出增量和 power plan。

局部阶段只能触碰该行星实体和允许的计数增量，不执行全局物流、量子或空间站边界。

### 4.3 稳定合并

`engine.ts:6461-6512`

- 先验证行星集合完整、无重复。
- 验证每个实体恰好由一个正确行星分区返回。
- 在任何写入权威状态前完成整批验证。
- 按 `planetId.localeCompare()` 稳定排序后合并。
- 累加 `totalProducedDelta`，而不是让并行分区竞争写全局计数。

这使多核结果与单核结果可做逐字段和状态哈希比较。

### 4.4 全局后置屏障

`engine.ts:6333-6449`

1. 结算轨道货运终端。
2. 在边界发生时先执行量子下载。
3. 执行输出侧传送带转运。
4. 再次排空配送枢纽。
5. 自动补充物流站翘曲器。
6. 先派遣本地物流，再派遣星际物流。
7. 推进本地与星际在途航线。
8. 再补充一次翘曲器并更新拥堵。
9. 运行银河物资出口器和出口项目。
10. 同步戴森兼容状态并更新发电。
11. 更新时间。
12. 对每个跨过的 5 秒边界依次处理站点模式切换、量子接入、空间站建设输入、系统枢纽物流和量子上传。
13. 更新终局十秒出口窗口和当前行星指标镜像。

边界采用循环而不是只处理最后一个边界，因此离线大步长不会漏结算。

## 5. 电力

电力按行星和电网分区：

- 风能、太阳能、地热、火电、聚变、人造恒星、射线接收和储能分别计量。
- 发电候选按优先级分配，消费者得到 `powerFactor`。
- 覆盖范围和电网 ID 共同决定连接状态。
- 燃料和蓄电使用批量闭式结算，避免百万堆叠逐件循环。
- 机器速度、增产剂功耗、物流派遣和巨构功能都读取同一 power plan。
- `getEntityOperatingStatus()` 将断电、缺料、满仓、等待路线等转换为 UI 可解释状态。

## 6. 生产与增产

机器周期由建筑速度、堆叠数、科技倍率、行星专长、配方时长和供电共同决定。运行前同时检查：

- 配方和建筑兼容。
- 所有输入是否足够。
- 输出容量和线路预留是否足够。
- 增产剂点数与模式。
- 交互锁、暂停和特殊建筑条件。

增产剂支持速度或额外产物模式，并单独计算喷涂物品消耗与功率倍率。生产统计从实际输入、输出和 `totalProduced` 更新，不从 UI 估算。

## 7. 传送带

线路持久字段包含：

- `source`、`target`、`itemId`、端口。
- belt tier、兼容 sorter tier、`lanes`。
- 优先级、cargo stack、route mode、route offset。
- progress、flow、congestion、monitor 和 `totalTransferred`。

关键规则：

- 只能连接同一行星的兼容源/目标。
- 端口、物流槽和配送枢纽端口必须满足占用与物品约束。
- 同一来源按高、标准、低优先级分组。
- 同优先级按稳定 ID 和持久 routing cursor 轮询。
- 一步中先消费旧输出，再预留新产出容量，再执行第二次转运。
- 并联线路范围 1 到 4096；增减会原子扣除或返还同级施工物品。
- `totalTransferred` 是权威累计整数；UI 的近五秒 `/s` 流量只是不持久化观察值。

`connectBeltsAtomically()` 对批量候选进行累计预检和最终原子提交，失败不会部分扣料。

## 8. 物流站与跨星系路线

物流站由槽位配置、无人机/运输船、翘曲器、最小载荷、优先级和路线策略共同控制。路线策略包括直达、中继优先和必须中继。

派遣过程：

1. 从只读索引查找相反模式且同物品的候选槽。
2. 按作用域、距离、优先级和稳定游标排序。
3. 计算本地或星际容量、载具、功率和翘曲成本。
4. 预留供给库存和需求容量。
5. 建立带 owner station、waypoint、距离、耗时和 cargo 的在途路线。
6. 到达和返程均按载具归属站结算。

`SimulationLookupContext` 缓存实体、行星、电网、槽位、路线、忙碌载具、供给预留和路径经济，缓存不进入存档。拓扑或科技环境变化时失效。

## 9. 建设、蓝图和制造中心

### 普通建设

建筑和线路放置走领域校验，材料原子扣除。删除会按规则返还缓存、在途物品和施工件。

### 蓝图

蓝图保存实体模板、线路、旋转、镜像、外部端口和可选资源锚点。资源锚点只匹配附近既有矿脉，不复制储量。部署先生成完整 plan，检查：

- 科技和建筑可用性。
- 行星兼容。
- 位置与重叠规则。
- 材料和建设能力。
- 资源锚点匹配。
- 特殊建筑唯一性。

随后创建建设队列，避免 UI 边拖边直接改变工厂。

### 建筑制造中心

制造中心把递归制造计划编译为确定性事务。任务保存配方选择、材料步骤、建筑或载具成品、WIP 和副产物。高堆叠下会寻找可证明重复的稳定周期并批量结算；无法证明时回退到逐任务路径。每步和每秒都有预算，预算耗尽仅暂停该任务，不阻塞其他系统。

## 10. 科研

科研支持：

- 当前有限科技。
- 暂停后恢复。
- 排队。
- 无限科研。
- 自动投入与银河出口自动化联动。

完成边界集中在领域函数中处理，能够修复“投入已满但尚未标记完成”的旧状态，并只执行一次奖励。离线宏观结算使用独立的整数/BigInt 账本，不直接把普通数值字段线性外推。

## 11. 银河与探索

`galaxy.ts` 用持久 seed 生成恒星类别、位置、行星模板、资源、环境倍率、航程和专长。生成后完整 profile 写入存档，迁移不会只凭 seed 重抽，保证跨设备一致。

探索、殖民和行星角色影响可用资源、建筑兼容和生产倍率。玩家命名、标签和备注经过长度与格式归一。

## 12. 戴森系统与终局

戴森系统包含：

- 多恒星系轨道。
- 太阳帆寿命与衰减。
- 电磁轨道弹射器目标轨道。
- 节点、框架、壳层和标准层模板。
- 火箭发射、帆吸收、结构点和发电。
- 射线接收器容量分配。

终局又叠加黑洞、时间扭曲、银河物资出口和活动。所有这些系统仍通过普通库存、电力、物流和研究边界推进，没有独立“免费进度条”。

## 13. 离线与纯挂机

### 普通离线

玩家可选择快速、精确或跳过：

- 精确：继续使用相同 `SimulationAdvanceSession`，按关键事件有界分块。
- 快速：先执行短精确校准，建立 affine contract，再推进长区间并做尾部验证。
- 保守：只结算可证明安全的聚合，冻结不确定的在途和瞬态。
- 跳过：明确放弃该时间段收益，不在以后重复结算。

策略会按实体、线路、存档大小、设备内存和状态波动性分类。失败原因区分取消、超时、Worker、内存、校准、合同、边界和非法源。

### 纯挂机

`pure-idle-macro-v3` 使用长期 Worker 会话：

1. 校准精确窗口。
2. 记录戴森、白糖、火箭、帆、活动和科研速率。
3. 按 30 秒现实时间桶推进。
4. 每 10 分钟做验证。
5. 校正库存/容量边界。
6. 停止时在 Worker 内生成终态 envelope。
7. 只有权威主存档写盘成功后才标记 committed。

Worker 崩溃时 durable recovery journal 保留继续或恢复依据。

## 14. 性能设计

- 持久 Worker runtime 避免每 tick 重新 hydrate。
- `SimulationLookupContext` 避免反复全量扫描。
- 动态路线只在脏时重建。
- 生产、线路、建设和电力采用批量账本。
- quiescent state 可快速前进。
- 多核仅并行无跨分区副作用的行星阶段。
- profiler 可记录复制、索引、电力、线路、生产、物流、建设、戴森和历史阶段，但不参与状态。
- legacy 全扫描和单核路径保留为确定性 oracle。

## 15. 主要风险

- 一个 `engine.ts` 同时包含查询、命令和模拟，局部改动可能影响广泛。
- 状态字段极多，迁移函数负担重。
- 运行时原地修改与公共不可变 API 并存，必须严格控制边界。
- 快速离线算法复杂，任何新字段都必须明确纳入、忽略或阻止近似。
- 内容包运行时会修改全局内容目录，需要 fingerprint 和恢复顺序保证一致。
