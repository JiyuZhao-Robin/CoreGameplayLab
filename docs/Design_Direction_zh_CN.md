# 《Helios / Space Idle》正式设计方向

> 生效范围：2026-09-10 起的当前产品方向。道路工业、成品建筑部署和固定 UI 规则覆盖本文件归档前的端口物流、现场施工、采矿舰和 1440×900 规定；完整旧文本保存在[归档](./archive/design-direction-before-content-sync-20260910.md)。

> 当前实现和实际验证记录见[内容同步状态](./Content_Synchronization_zh_CN.md)与[星球共享库存与道路工业](./Planetary_Industry_Roads_Design_zh_CN.md)。本文定义目标与边界，不把目标写成已经完成的功能。

## 产品定位

这是一款单恒星系的太空工业管理游戏：玩家在有限行星画布上规划产线与道路，以工业能力支撑勘测、舰队、跨地点航运、科研和唯一的恒星能源终局。

```text
勘测资源与环境
        ↓
部署开发核心与工业建筑
        ↓
道路接通电力、自动搬运和共享库存
        ↓
制造材料、建筑、舰船和补给
        ↓
通过星际航运把工业能力送往远端地点
        ↓
研究、舰队行动与巨构项目打开下一阶段
```

吸收 Factorio 的空间生产与瓶颈、DSPONLINE 的工厂配方与快速配置、Anno 的道路服务和单地库存、Stellaris 的星系地图与舰队组织；不引入人口/市场/外交大系统，也不把宏观建筑拆成逐台机器微操。

## 已批准的工业规则

### 星球、道路与库存

- 每颗星球具有自己的有限逻辑画布和地形边界。Earth 为 1024×640；更大世界最高 4096×2560。画布尺寸决定实际可建设面积，不通过缩小整颗星球规避规模。
- 地形与资源是稀疏、确定性生成的描述；水体和山脉禁止建筑与新道路。渲染只处理视口附近区块并使用 LOD，模拟不因视口隐藏而停止。
- 当前 Earth 生成全部 15 种 DSP 原料；气态巨星额外生成氢、氘和可燃冰兼容矿区。基础、进阶和稀有资源如何按地点分层仍待用户决定，不能把现状描述为已平衡的资源地理。
- 道路连接同一分量内的电力和本地自动运输。建筑不接道路就没有电；道路不要求玩家再画 CARGO/POWER 端口线。
- 一个 Location 只有一份共享库存，每种物品有独立容量。仓库只提供道路接入与装卸，不能制造第二份库存；机器缓存、道路在途与星际在途物资各自拥有明确保管域。
- 本地道路不引入铁路、长途卡车线路、分区库存或手动调拨。现有跨地点航运是唯一的长距离运输层。

### 建设与开局

- 普通建筑是可制造、可运输的成品。玩家消耗成品部署建筑；缺货时保留幽灵并等待到货。普通建筑没有现场建材拨款或施工进度条。
- 新游戏由玩家先选择位置部署一件星球开发核心。核心提供 400 kW、共享库存接入与道路服务，并仅一次发放两矿机、两锻炉和一台自动制造机。
- 不预放工业建筑、仓库或太阳能阵列。后续电力与建筑都由工业制造；远端地点运输开发核心和建筑成品，不重复领取地球开局包。
- 巨构、研究、舰船和其他明确的项目运行时可以有独立成本与阶段，但不能借此恢复普通建筑的现场施工经济。

### 生产、DSP 适配与表现

- 机器从兼容配方中选择生产项目，具有输入/输出缓存、反压、道路供电与自动取送料。机器配置复制是快速配置工具，不等价于区域蓝图。
- 已适配的 DSPONLINE 工厂内容包括 78 种源物品映射、39 栋建筑、80 条源配方、39 个建筑成品制造配方与 5 条矩阵选择变体。普通配方、燃料机、蓄能、能量交换、接收站、喷涂、矩阵研究、发射和指定项目效果都必须服从本项目的道路与 Location 权威。
- 美术必须是入库资产并保留生成来源。建筑、物品、地形与道路图集可以在近景使用；远景代理和调试几何不是“完成美术”的证明。

## 其它核心系统

- 勘测按 `UNKNOWN → DETECTED → SURVEYED → DEEP_SURVEYED` 推进，环境、资源情报和远端部署难度必须可解释。
- 舰船是工业制造的实体资产，用于战斗、探索与实际跨地点运输；舰船不再采矿、施工或常驻打捞。舰船装配保留独立的节点画布、BOM 与存档提交边界。
- 研究以材料、条件、原型和项目阶段推进；矩阵研究只为现有研究系统提供工作积分，不建立平行科技树。
- 战斗、远征和有限战后残骸保留独立运行时。它们可以提供资产与情报，但不能形成绕过 Factory 的普通资源生产旁路。
- 当前终局是单一 `stellar_energy` 项目；其材料、物流、维护和阶段状态必须可追溯。

## 范围边界

| 主题 | 当前决策 |
| --- | --- |
| 星系范围 | 正式核心版本只运行一个 `sol` 恒星系；“星际航运”指现有跨地点航运。第二恒星系、跨恒星殖民与跨恒星物流尚待未来范围确认，不进入当前 Roadmap。 |
| 戴森球 | 当前只适配帆、火箭、接收站、光子与项目效果。完整球壳几何、帆吸收和恒星亮度研究未获本轮批准。 |
| 有限矿量 | 当前矿区持续开采。是否以后加入有限/高品位矿区是待用户确认的经济决策，不列作已批准实现。 |
| 区域蓝图 | 仍未实现；未来需要实体、旋转、资源锚点、道路与幽灵的原子部署设计。 |
| 地形改造 | 尚未实现。 |
| 车辆表现 | 道路在途物资可投影；完整车辆/无人机实体、动作与服务范围可视化尚未完成。 |
| 大工厂性能 | 视口裁剪、区块和 LOD 是当前契约；满负载性能基准仍需单独验证。 |

## 固定 UI 契约

- 所有生产 UI 以 **1920×1080** 逻辑视口设计，**3840×2160** 为主要视觉验收目标。
- 物理窗口只做一次统一 `canvas_items + keep` 缩放与居中留白；不得改变布局比例、字体档位、侧栏状态或页面结构。
- 工厂、星系图、研究、舰船装配与星球表面各有独立内容相机；窗口缩放不得补偿其平移或缩放。
- UI 验收使用受影响的固定布局、缩放契约和窗口矩阵测试；J1–J10 旅程链不能替代功能测试。
