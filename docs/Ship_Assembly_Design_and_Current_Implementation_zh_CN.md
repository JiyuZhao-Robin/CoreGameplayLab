# 舰船装配设计理念与当前实现

> 当前实现快照：2026-09-01
> 产品版本：`1.32.0-ship-role-cutover`
> 存档 Schema：`38`

本文总结当前项目中“舰船安装”的正式含义，即舰船模块装配（Ship Assembly / Loadout），并以当前代码、内容数据和专项测试为准。旧文档中“改装只消耗 BOM 差额”“尚无可视化装配编辑器”等描述已经过时，不代表当前实现。

## 1. 一句话概括

舰船装配不是给舰船增加一个抽象战力数字，而是让玩家在舰体的物理插槽、接口类型、尺寸和工程预算内亲自定义一套模块组合；这套组合随后成为真实的造船或改装订单，消耗完整工业 BOM 和时间，并最终决定实体舰船可以承担的战斗、勘测、物流与支援职责。

## 2. 术语与对象边界

| 概念 | 当前数据 | 含义 |
|---|---|---|
| 舰体定义 | `content.ships` | 舰体尺寸、插槽、允许模块尺寸、质量/电力/散热容量、基础战斗与货运参数 |
| 舰体建造计划 | `content.ship_construction_projects` | 舰体的解锁与建造规则、基础成本、默认模块和船厂工程等级要求 |
| 舰船设计 | `state.ship_designs` | 在装配画布中创建的命名设计，保存舰体、模块节点、位置和玩家连线，用于建造新舰 |
| 装配预设 | `state.saved_loadouts` | 从现有实体舰船保存的模块清单，绑定同型号舰体，用于现役舰改装 |
| 实体舰船 | `state.ships` | 具有永久 ID、名称、状态、地点、服役记录和当前已安装模块的资产 |
| 普通模块 | 模块定义 ID | 不是库存实体；应用装配时按完整 BOM 现场制造并安装 |
| 特殊装备 | `state.equipment_instances` | 有独立 `EQUIP-*` UUID、存放/预留/安装状态和唯一所有权的稀有资产 |

“舰船设计”和“装配预设”目前是两套相邻但不同的工作流：前者服务于新舰建造，后者服务于已有舰船改装。

## 3. 核心设计理念

### 3.1 管理设计，而不是管理普通零件库存

普通舰载模块被视为“设计定义 + 制造 BOM”，不作为可堆叠、可运输、可囤积的库存物品。造船或改装时，星港直接消耗原材料制造目标装配所需的整套普通模块。

这样保留了工业成本和供应链压力，同时避免把舰船装配变成逐件搬运、找库存和管理旧零件的行政负担。

### 3.2 玩家亲自装配，不使用模板自动连线

新设计从空白画布开始。玩家必须拖入一个已解锁舰体，再拖入零件并把每个零件连接到舰体中的兼容插槽。拖入节点不会自动生成连接，只有玩家建立的连接才进入设计存档。

### 3.3 舰体是有物理拓扑的装配背板

舰体不是一排同质槽位。当前视觉与规则共同表达：

- 能源核心位于舰体中央，是画布设计的必需模块。
- 推进接口位于舰体上部。
- 武器与特殊插件分布在舰体两翼。
- 护盾、货舱等结构件位于舰体下部。
- 小型舰体插槽少、尺寸上限低；大型舰体拥有更多、更大的插槽。

舰体轮廓、长宽、插槽直径与画布比例使用统一物理尺度，因此大型舰体在画布上确实比小型舰体更大，而不是只更换一张图标。

### 3.4 接口形状承担规则提示

| 安装族 | 形状 | 当前对应内容 |
|---|---|---|
| 武器 | 三角形 | 火炮、能量武器等 |
| 特殊插件 | 五边形 | 传感器、火控、维修、深度勘测等 |
| 推进 | 菱形 | 基础与高级推进器 |
| 船体结构 | 方形 | 护盾、货舱、大宗/低温货运结构等 |
| 能源核心 | 圆形 | 民用与高输出反应堆核心 |

接口的方向、安装族、形状、占用状态和尺寸等级都必须匹配。未连接插槽为灰色空心；拖动连线时只有兼容插槽高亮；连接完成后插槽按类型着色并变为实心。

### 3.5 UI 表达意图，领域层决定真伪

画布负责交互反馈和草稿，不直接修改舰船或船厂状态。保存和建造前必须再次经过 `Game.ship_design_validation()`；即使伪造 UI 数据，也不能绕过领域校验。

### 3.6 装配必须产生真实工业成本和时间成本

装配不是免费切换标签：

- 新舰成本 = 舰体建造成本 + 初始装配中全部普通模块的 BOM。
- 改装成本 = 目标装配中全部普通模块的 BOM，而不是与旧装配的差额。
- 相同普通模块不会抵扣，因为普通模块不是跨改装周期永久存在的独立资产。
- 制造时间与安装时间分别计算，但当前合并为一个连续的 100 段改装项目。
- 取消改装会恢复原装配，但已投入的制造材料不返还。

### 3.7 舰船职责来自当前装配

舰体本身不授予任务能力；能力由当前安装模块累加。当前主要影响包括：

- 武器、护盾、命中、电子战、弹药和攻击循环等战斗参数。
- `long_range_scan`、`survey_support` 等勘测与远征能力。
- `bulk_freight`、`insulated_cargo`、`high_speed_freight` 等专用运输资格。
- 模块货舱容量对物流吞吐的增量。
- `repair_support` 对停靠舰船修理速度的支援。
- 推进、隐身、抗辐射等路线或任务门槛。

Schema 38 已明确废止舰船承担常规采矿、采气和施工生产的旧路线；这些长期工业工作现在归属于方格工厂世界。舰船保留移动任务、物流、勘测、战斗和舰队支援职责。

### 3.8 普通模块与特殊装备采用双重资产语义

普通模块只保存定义 ID，改装时重新制造；Boss 或任务回收的特殊装备则保留 UUID，只能由一艘舰船占有，拆下后回到星港存储。这个边界让常规模块保持低管理负担，同时保留稀有战利品的唯一性。

## 4. 当前闭环

```text
内容数据
  └─ 舰体、插槽、模块、BOM、建造计划
       ↓
空白装配画布
  └─ 拖入舰体与模块 → 玩家手动连线 → 领域校验
       ↓
命名舰船设计（ship_designs）
       ↓
船厂订单
  └─ 快照模块清单 → 登记需求 → 分段消耗完整 BOM → 完工
       ↓
实体舰船（ships）
  ├─ 战斗 / 远征 / 勘测 / 物流读取当前装配
  └─ 保存装配预设（saved_loadouts）→ 完整 BOM 改装 → 新装配
```

## 5. 已经实现的部分

### 5.1 数据驱动的舰体与模块内容

当前 `data/content.json` 包含：

- 15 个舰体定义，其中 14 个拥有可建造计划，另 1 个是开局实体舰体。
- 18 个模块定义：17 个普通模块、1 个 UUID 特殊装备。
- 5–11 个插槽的舰体规模跨度。
- `weapon / shield / drive / utility / core` 五类逻辑槽位。
- S、M、L、XL、XXL 五级接口系统；当前模块内容实际使用 S、M、L，大型舰体已提供 XL、XXL 插槽上限。
- 17 条普通模块 BOM 配方，覆盖当前所有普通模块。

内容校验器会检查舰体插槽总数、默认装配合法性、普通模块经济路径，以及默认造船计划不能凭空生成特殊装备。

### 5.2 可交互装配画布

`ShipAssemblyMapView` 已实现：

- 空白画布起步，以及“舰船 / 零件”两个拖拽 Palette。
- 只展示当前已解锁舰体计划和已揭示模块。
- 画布中最多一个舰体，但可以放置多个同定义模块节点。
- 点阵网格、20 像素吸附、缩放、平移、小地图和“适配全部”视图。
- 舰体与模块节点移动、选择、删除、断开和重新连接。
- 直角短引线—共享横轨—短接入布线，带圆角和节点避让。
- 自定义连线绘制、命中测试与选中反馈。
- 连接过程中兼容、静默、不兼容、已连接等插槽视觉状态。
- 舰体正投影轮廓、内部结构线、舱段、工程网格、尺寸标注和 42 米参照物。
- 根据舰体轮廓与插槽直径自动寻找不越界、不重叠的插槽位置。
- 侧栏查看舰体、模块指标、当前校验结果和整舰材料清单。

### 5.3 双层连接校验

画布层立即拒绝：

- 反向连接或非“模块 → 舰体插槽”的连接。
- 槽位/安装族/形状不匹配。
- 模块尺寸等级大于插槽上限。
- 一个模块连接多个插槽，或一个插槽被多个模块占用。

领域层保存前重新检查：

- 建造计划存在且已解锁。
- 设计中恰好有一个与计划匹配的舰体。
- 模块存在、已揭示，节点 ID 和连接目标有效。
- 每个模块恰好连接一个有效插槽。
- 接口族和模块尺寸合法。
- 中央能源核心已经安装并连接。
- 各类槽位数量未超限。
- 模块总质量、电力需求和热负荷不超过舰体容量。

### 5.4 命名设计与持久化

玩家可以：

- 为同一舰体保存多个命名舰船设计。
- 重新载入设计并继续编辑。
- 更新或删除已保存设计。
- 保存模块节点位置和玩家建立的连接，而不只保存最终模块列表。
- 通过 Save Schema 序列化 `ship_designs`、下一个设计序号和相关船厂运行态。

进入船厂时会再次校验设计，并把模块清单快照到订单的 `custom_modules`；之后修改或删除原设计不会改变已入队订单的实际装配内容。

### 5.5 真实船厂订单

当前船厂已实现：

- 从已保存设计创建 1、5、20 艘批次订单；领域接口允许 1–100 艘。
- 队列持久化、上移/下移、取消、阻塞原因和进度展示。
- 船厂工程等级门槛与星港供电/速度修正。
- 每艘舰船以 100 个进度段逐步消耗材料。
- 舰体基础材料、固定成本和完整初始装配 BOM 的统一计算。
- 缺料时进入 `BLOCKED`，材料恢复后继续推进。
- 造船需求进入共享 Demand Registry，供经济诊断与规划器读取。
- 批量订单逐艘完工，每艘获得独立 `SHIP-*` ID、名称、服役时间和实际模块清单。
- 舰船属于离散资本项目，不接受生产力额外产出，避免产生免费进度或额外舰船。
- 取消订单时已消耗材料不返还，尚未消耗部分不再继续承诺。

### 5.6 现役舰改装

舰队名册已实现另一条面向实体舰船的改装路径：

- 保存、应用、删除同舰体型号的命名装配预设。
- 直接安装、移除或替换单个模块；这些快捷操作最终都会构造完整目标装配并进入同一改装事务。
- 统一的 `ship_loadout_availability()` 在 UI 出按钮前检查停靠状态、模块设计、特殊装备所有权、装配合法性和完整 BOM 库存。
- 只有状态正常、已停靠且未封存的舰船可以改装。
- 改装启动后舰船进入 `REFITTING`，暂时清空现有安装位，并被排除在任务之外。
- 普通模块完整 BOM 在项目开始时一次性扣除。
- 制造时间和安装时间分别保存，当前合并为一个 100 段连续项目。
- 完工后安装目标模块、恢复 `DOCKED`，并记录当前装配预设 ID 与改装统计。
- 取消后恢复原装配和特殊装备所有权，但不退还普通模块制造材料。

### 5.7 特殊装备唯一性

特殊装备已实现的部分包括：

- 任务效果生成独立 `EQUIP-*` 实例。
- `STORAGE / RESERVED_REFIT / INSTALLED` 状态。
- 同一实例不能同时安装在两艘舰船上。
- 改装时可以复用本舰原装备或从星港存储预留。
- 被替换的特殊装备在改装完成后回到存储。
- 取消改装会恢复原舰的特殊装备所有权。
- 拆解舰船时特殊装备返回存储，而不是作为普通材料销毁。

### 5.8 装配对其他系统的实际影响

当前装配不是展示数据，已有多个系统直接读取它：

- `CombatResolver` 将武器、护盾、装甲、精度、电子战、攻击触发器和弹药规则汇入单舰战斗演员。
- Survey Mission 按安装能力检查逐级勘测资格，并用能力值缩短任务时间。
- Expedition 节点按推进、武装、护盾、传感器等能力检查舰队是否满足条件。
- Logistics 按真实货舱容量和所需模块能力决定专用运输舰是否合格，并计算路线运力。
- 舰队修理和远征支援速度读取 `repair_support` 与 `survey_support`。
- 名册会从装配实时投影大宗货运、低温货运、维修支援、勘测支援、武装等职责标签。

## 6. 当前尚未统一或尚未完成的边界

这些项目不能写成“已经完整实现”：

1. **造船画布与现役舰改装尚未合并。** 画布设计只能直接进入新舰建造；现役舰仍通过列表、快捷安装/移除/替换和 `saved_loadouts` 改装，不能把一个 `ship_designs` 画布方案直接应用到现役舰。
2. **核心必装规则只在画布造船校验中强制。** 通用 `ship_loadout_error()` 目前只检查槽位上限、尺寸和工程预算，因此列表式改装路径尚未强制保留能源核心。
3. **特殊装备的造船画布路径尚未闭环。** 特殊装备 UUID、存储和改装所有权已经实现，但画布 Palette/保存校验目前没有禁止或预留特殊装备；自定义造船订单只快照模块定义。这条路径仍需增加“必须拥有具体 UUID、不能由船厂复制”的约束。
4. **模块可用性规则不完全一致。** 画布使用“定义已揭示”作为可放置与保存条件；现役舰改装使用更严格的 `module_design_available()`，还会检查 BOM 配方要求和制造设施能力。
5. **插槽规格仍有生成式简化。** 每个舰体使用一个统一的最大接口尺寸；Utility 插槽的“特殊/结构”数量根据默认装配推导，而不是在内容中逐插槽显式编写。
6. **连线目前表达安装关系，不表达系统网络。** 节点位置和布线路径不会产生射界、相邻加成、供电拓扑、热流或损伤分区；模拟最终读取的是通过校验得到的模块清单。
7. **预算反馈仍偏结果式。** 领域层已经校验质量、电力和散热，但画布侧栏还没有完整的已用/上限仪表、变化对比和任务适配评分。
8. **部分历史文档和旧测试仍引用已退役规则。** 例如旧的采矿激光/采气/施工舰职责、BOM 差额改装和“无可视化编辑器”描述，应以 Schema 38 当前代码与本文为准。
