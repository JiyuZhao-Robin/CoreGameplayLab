# 行星无人机物流：当前规则与实现状态

更新：2026-09-11。本文记录用户批准的道路替代方案、当前实现及本轮验证边界。它替代旧道路设计中的本地运输和接路供电规则；建筑成品部署、矿区、地形及星际物流等独立要求继续有效。

## 已批准的玩家规则

本地运输由无人机塔负责。塔的覆盖范围是圆形；生产建筑累计一批产品后，无人机先飞过去取货，**实际拿到货物时**再检查该塔范围内的原料需求。需要此物品且库存不足的建筑优先收货，否则货物送回塔存储。

输入补货目标按十次配方计算。例如电路板每次需要 1 铜板、2 铁板，则铜板目标为 10，铁板目标为 20。已有输入与已承诺在途输入共同占用目标，不能让多架无人机重复填补同一缺口。

行星经济库存仍只有一份：`locations[world.location_id].inventory`。所谓“送回塔存储”，是经该塔存入这份 Location 库存。塔和其他仓库不另存一份重复物资。生产建筑输入、输出缓冲与无人机实际携带的货物是独立的实物保管位置，只有完成转移才更换保管方。

## 运输状态与供需判断

1. **空机前往取货 `TO_PICKUP`。** 调度器先预留源建筑的可取产品，货物此时仍在生产建筑的输出缓冲。其他塔也必须扣除这份源预留，避免重叠覆盖重复派单。派单阶段不会预定最终生产消费者。
2. **抵达取货点。** 确认产品仍足量后，从源输出扣除并放入无人机的 `cargo`。这一步才检查所属塔圆形范围内的当前消费者，选择配方接受该物品且仍有缺口的建筑。取货期间新出现或消失的需求会参与这次判断。
3. **向消费者配送 `TO_DELIVERY`。** 本次配送量不超过无人机载货、消费者当前缺口和输入缓冲实际余量。在途配送占用其承诺的原料数量；到达后再次确认接收条件。若只缺 3 件，10 件货物只交付 3 件，余下 7 件保留在无人机上。
4. **返回所属塔 `RETURNING`。** 没有消费者时携货返回；完成消费者配送后携余货或空机返回。余货成功存入共享 Location 库存后才离开无人机保管。空机也必须飞回塔，返回途中仍占用该塔的一架运力，不能立即在塔上重复派出。
5. **塔库存补货。** 需求可以晚于生产出现：调度器会从共享库存取出可用物品，由覆盖目标的塔送去补足输入。单次最多 10，并允许不足 10 的实际缺口。不会要求必须碰巧有生产者此刻取货，才能使用已经存下来的原料。

单种原料缺口为：`max(0, 配方系数 × 10 − 已在输入缓冲的数量 − 承诺送入的数量)`，还要受所有输入占用后的物理容量限制。例如铜 8、铜在途 2，目标 10，则铜已无新缺口；铁 7、铁在途 10，目标 20，则还可接收 3 铁。内容加载会让输入缓冲至少容纳十次完整配方，避免多原料配方被过小总容量锁死。

普通新产物不足 10 时留在输出缓冲，继续等待凑满。2026-09-11 建筑归并更新：**建筑成品有 1 件即可取回共享库存**，使第一次扩张不必先制造十栋楼。**更换配方退回的旧原料是例外**：它们被标记为待退料，即使只剩 1–9 件也能回收，避免旧原料永久卡在无法消耗的缓冲中。改变配方不会凭空清空原料；历史超出新容量的缓冲也保留，待运输腾出空间后恢复生产。

燃料发电、能量交换器和增产剂等既有物资需求仍通过有限输入缓冲与实际运输处理。它们的专用目标由运行规则计算，不把燃料或能量变成隐含无限供给。

## 电力、道路退役与存档

当前电力在同一 Factory 世界内统一分配，不再要求建筑接路，也不依赖无人机覆盖圈。覆盖圈约束本地取送货，电量不足仍影响生产。无线分配保留现有发电、燃料、电池和能量交换结算，保持真实能量收支；不会因为移除道路而赋予免费无限电力。

道路工具、拖动铺路/拆路手势及道路绘制已经从 Factory UI 移除。新 `BUILD_ROAD`、`REMOVE_ROAD` 命令返回 `ROADS_RETIRED`。手动 Factory 货运端口和电力连线继续停用；星际运输保持独立。

旧存档中的道路布局保存在 `legacy_roads_archive`，仅作为惰性历史数据：不渲染、不占地、不导电、不派单。旧道路任务里的货物已经离开原源建筑，归一化会把这些实物任务一次性移入 `drone_shipments`，保留货物而不是按道路几何一起删除。旧任务异常或缺少可用塔时需保留实物并报告阻塞；不得通过再次扣取源货物恢复运输。

无人机任务以 Dictionary 持久化；UI 获得按 ID 排序的只读 Array 投影，包含 `tower_id`、收发端点、`phase`、`status`、实际 `quantity`、位置、航向和飞行进度。空飞数量是 0，仍作为可见飞行显示。界面只在两次已观察到的位置之间插值，不外推越过最新真实位置。

库存适配器 `SimulationEngine.factory_inventory_context` 是临时引用，绝不能序列化进世界。`SpaceGameState.factory_world_item_ledger` 计入无人机实货；`LogisticsEngine.incoming_storage_reservation` 协调其他同地点世界及星际入库预留。运送与入库仅改变保管位置，不记作新增产出或生产消耗。

## 美术来源与资产边界

新塔使用 [Krastorio 2 Assets](https://codeberg.org/raiguard/Krastorio2Assets) 的 `small-roboport` 塔身、阴影、待机动画与灯光，来源许可记录为 LGPL-3.0。无人机使用 [OpenHV](https://github.com/OpenHV/OpenHV) 的 `drone2` 八方向、每方向两帧图像，作者 Pawel Dzierzanowski，来源许可记录为 CC BY-SA 4.0。无人机按原项目调色板和透明索引转换；塔 PNG 保持原始内容。

它们是实际随项目保存的**预渲染二维模型图像**，上游资源不包含本次可交付的可编辑三维模型。不能把它们描述为已找到或已制作 `.blend`、`.glb` 等三维源模型，也不是以调试几何代替完成美术。

追溯信息与文件哈希见 [运行资产 manifest](../assets/ui/factory/drone_tower/manifest.json)；原始信息、调色板、声明和许可见 [来源目录说明](../assets/models/drone_tower/README.md)。显示适配器为 [FactoryDroneArt](../src/ui/workspaces/factory/factory_drone_art.gd)。
